## P0 · 设计冻结（本批）

**目标**：把"要做什么、不做什么、为什么"钉死，避免实现阶段自由发挥。

| 交付 | 文件 |
|---|---|
| 源码审计（已有/缺失/待决） | `SOURCE_AUDIT.md` |
| 完整设计 | `DESIGN.md` |
| 15 条决策 | `DECISIONS.md` |
| 可量化验收 | `ACCEPTANCE_CRITERIA.md` |
| 三张图 | `LOOP_DIAGRAM.svg`、`SYSTEM_MAP.svg`、`ROADMAP.svg` |
| 本文件 + 报告 + 保护审计 | `ROADMAP.md`、`REPORT.md`、`Evidence/*` |

**出口**：复审确认"A-01～A-08 全绿"，并至少对 **D-02 / D-08 / D-15** 给出结论。

**风险**：设计过度（写成实现）。缓解：本文件所有条目都可映射到 `文件:行号` 或明确标注"新增"。

## P1 · 信息层（零 schema、零经济、零数值）

**目标**：让玩家在出征前、局内、结算后都能回答"我在做什么、还差什么、下一步"。

| 复用 | `earnedRemaining`、`events[].used`、`enemies[].health`、`resources[].health`、`gear[].origin` |
| 改动面 | 新文件 1（~250 行）+ 单元断言；**不接入存档** |

| 风险 | 计数口径写错 → 用 D-08 硬规则 + 反例 D-01 |

## P2 · 持久化与回执（存档修订，单独批次）

**目标**：让"选择"被记住，让"达成"有据可查。

| 项 | 内容 | 依赖 |
|---|---|---|
| P2-1 | 技能槽预设（7 武器 × 2 槽） | D-03 |

## P4 · 内容深化（**不在本授权范围**）

以下四项在设计中明确**不做**，仅登记为未来方向；任何一项都需要新的授权批次与数值平衡方案：

| 方向 | 触碰的禁区 | 前置条件 |
|---|---|---|
| 每武器第 3 技能（D-04） | 技能冷却/伤害/动画 | 新内容批次 + 平衡方案 |
| 新武器配方（D-05） | 材料产出/消耗 | 经济授权 |
| 单件升级/重铸（D-10） | 武器伤害/随机流 | 经济 + 随机流授权 |
| 地区难度档（D-13） | 敌人数值 | 战斗数值授权 |

## 批次纪律

1. **一批一分支**，命名 `feature/ux-progression-01-p1` 等；不合并 main。
2. **不跨阶段混提交**：P1 不得顺手加存档字段。
3. **每个阶段独立可回滚**：P1 回滚 = 删 UI 代码，零数据影响；P2 回滚必须带迁移逆操作。
4. **每阶段独立复审**：不因 P1 通过而默认 P2 通过。
5. **证据随批归档**：Player run、断言、哈希按 `Evidence/` 规范。
