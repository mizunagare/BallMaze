# GAMEPLAY-UX02：战斗表现与操作反馈技术完善

- 项目：万象归途（WanxiangGuitu）
- 仓库：mizunagare/BallMaze
- 固定制定基线：ab6b350ba900894f74efe29a803631271ed6ce7a
- 目标：完善玩家能从画面、声音、动作和镜头中读取的战斗反馈
- 性质：先审计现有表现系统，再修复可复现缺陷；不做无依据的美术重制或数值平衡
- 人工试玩当前不可用：所有人工可读性、舒适度、趣味性和最终手感继续 NOT_RUN
- 完成后：提交证据、核对完整SHA并暂停独立复审

## 1. 产品目标

使玩家更清楚地感知：
- 自己何时开始攻击、何时真正释放、何时命中；
- 普攻、技能、不同武器攻击的动作与声音差异；
- 自己受击、敌人受击、精英/Boss受击与死亡；
- Boss攻击预警、攻击方向/区域、实际释放与结果；
- 闪避、武器切换、技能冷却和战斗状态变化。

原则：反馈必须对应真实游戏事件。不得用纯视觉/音频假象暗示未发生的伤害、命中、格挡或奖励。

## 2. 固定基线已知的表现架构（开工必须重读）

- CombatFeedback.cs：场景级表现入口，负责Swing/Hit/Hurt/Defeat/Cast/BossWarning/Slam音效、特效、伤害数字、受击覆盖和镜头震动；有EffectLimit=24、VoiceLimit=10、NumberLimit=32及独立System.Random，表现随机不应改变游戏AdventureRandom。
- FantasyActorVisual.cs：动作播放、AttackTimed、Hurt、Recoil、死亡表现；按当前武器类型选择剑/矛/弓/法杖动作片段。
- CatActorVisual.cs：将原骨骼动画载体绑定猫族模型；保留原Renderer/骨骼绑定合同。
- OrbitCamera.cs：相机跟随、鼠标视角、Shake及遮挡处理。
- EnemyAttackSignal.cs：普通敌预警表现，不参与伤害判定。
- BossWarningGeometry.cs、ForestBossTelegraph及BossBrain预警：Boss预警几何/表现与真实攻击合同需要逐招核对。
- AdventureCombat.cs：攻击动作、武器类型、实际释放时间、MeleeGeometry与远程瞄准的业务入口。不得把表现时间误当成伤害释放时间。
- CombatHealth/CombatFeedback事件链：实际Damage观察是命中反馈唯一可信来源之一。

以上是源码入口线索，不预先认定存在缺陷。Codex需查找当前实际调用链、场景挂载、资源依赖和各武器/敌种覆盖。

## 3. 审计范围

### 3.1 玩家武器反馈
对剑、矛、弓、法杖分别梳理：
- 输入开始、动作起始、实际攻击释放、命中/未命中、动作结束/取消的时间线；
- 普攻与技能动作片段是否匹配武器类型；
- 动作片段时长、释放时点、攻击冷却是否有错位；
- 近战挥击/突刺特效与真实攻击几何是否一致；
- 弓/法杖的发射方向、枪口/弹体、施法音效与实际释放是否一致；
- 武器切换/攻击取消/暂停/死亡时是否残留动作或声音。

不修改攻击伤害、范围、冷却、释放比例、命中几何或武器特性数值。

### 3.2 命中、受击和死亡反馈
检查：
- 只有实际Damage才触发命中数字、命中特效、受击音效和震动；
- 伤害数字显示实际承伤值，不把预测伤害/重复碰撞当真实伤害；
- 玩家受击与敌人受击的视觉/声音区分；
- 精英、普通敌、Boss及致死一击的反馈层级；
- 死亡表现、碰撞关闭、掉落/结算与视觉隐藏的先后关系；
- 同一Damage事件是否被重复表现，回调顺序是否安全；
- 表现对象销毁、场景卸载、暂停和恢复是否清理资源。

### 3.3 Boss预警与攻击表现
逐招检查普通BossBrain与森林BossBrain：
- 预警形状、方向、落点、锁定位置与真实判定是否一致；
- 前摇时间显示是否与真实释放时刻一致；
- 冲锋/扇形弹幕/圆形范围/岸边方向招式的表现是否能区分；
- 遮挡、取消、目标移动、Boss受击、暂停、禁用和死亡时预警是否正确清除；
- 预警不可直接伤害玩家，不得与真实判定产生不一致提示。

### 3.4 音效、镜头和表现资源
- 音效事件映射、声道上限、同帧声音抢占/冷却、音量和距离衰减；
- 镜头震动强度、持续时间、叠加、暂停和清除；
- 特效池容量、对象复用、Material所有权、销毁与场景卸载；
- 缺失AudioClip/Shader/Material/Prefab时的降级路径；
- 低配/非开发Player中的表现开销采集能力。

不以“看起来更炫”为由增加持续粒子、屏幕闪烁或大范围震屏。

## 4. 允许修改范围

优先在现有CombatFeedback、FantasyActorVisual、EnemyAttackSignal、Boss预警表现、OrbitCamera及对应资源上做小改动。只有确认缺陷且无法在现有入口修复时，才提出新增表现资源/脚本。

每个修改必须：
1. 有修复前可复现负例或明确的合同违反；
2. 描述玩家能观察到的影响；
3. 说明表现触发对应的真实业务事件；
4. 不改变伤害/命中/冷却/随机/存档等游戏逻辑；
5. 有修复前后相同输入验证及资源生命周期检查。

如果当前表现已经符合合同，标记“已有实现/补证完成”，不要为了产生代码差异而重做。

## 5. 明确禁止

- 不改武器伤害、攻击范围、攻击冷却、释放时点、弹速、护甲、敌人HP/伤害、掉落、经验或经济。
- 不改AdventureRandom、Run随机流、v9存档结构、迁移、结算、地图和AI行为。
- 不引入大型动画框架、Timeline重构、全局VFX框架或新的音频中间件。
- 不将动画播放、特效生成、音效播放作为真实命中证据。
- 不用自动化截图宣称真人能看懂预警或感到打击感良好。
- 不因表现测试失败而关闭碰撞、跳过Damage、修改目标HP或注入奖励。

需超出范围时停止并另提任务。

## 6. 验证矩阵

至少覆盖：
1. 四武器普攻与技能的动作选择、起始/释放/结束时间线；
2. 命中、未命中、被遮挡取消、攻击取消和暂停时表现触发；
3. 实际Damage事件与伤害数字/Hit/Hurt/Defeat反馈一一对应；
4. 玩家、普通敌、精英、Boss受击及死亡表现；
5. Boss各招式预警形状/方向/范围与真实判定几何；
6. 预警取消、目标无效、死亡、禁用、暂停、场景卸载；
7. 音效通道限制、声音抢占、距离衰减与缺资源降级；
8. 特效数量上限、Material/对象所有权、场景卸载清理；
9. 相机震动叠加、暂停、恢复和清除；
10. 非开发Player实际运行（若环境允许）与纯发行构建分层报告。

固定输入和测试角色/敌人状态；记录seed、Run/attempt、武器、攻击ID、真实释放帧、Damage事件ID、表现事件、音效/特效资源及进程退出码。未实际采集的指标标记NOT_RUN/UNRESOLVED，不填零。

自动化可以验证触发合同和时序，不能验收动作观感、音效质感、可读性、舒适度和最终打击感。
