## 实际入口

打开 ForestRuins，运行，营地选择出征；选「森林探索 · 兴趣点与路线」。原「冒险测试」和「原波次测试」仍可选择。旧的在途存档继续原模式，必须先正常撤离或放弃、结算，再选择新模式；不会把旧局强行改成森林。

## 增量实现

- 存档 v9：地面掉落每 256 条形成独立 JSON 页，SHA256 内容寻址。页 Flush(true) 并持久化后，主存档才引用清单，再原子替换。读取验证页大小、哈希、条数后完整恢复，再执行原有装备/来源/结算校验。没有截断、合并数值、自动拾取或自动入仓。
- 2048 不再是运行世界的总数上限。主文件仍保留 8 MiB 元数据预算，写入前也检查同一预算，避免生成自己读不回的文件；实际 IO/空间失败保留原档、结算停留重试。分页不按总掉落数设置新的替代常数。
- 正常运行和待提交结算都保存完整地面掉落；成功/失败只按原规则处理实际背包物资。未拾取地面物不会作为成功收益领取。已结束 Run 的地面物不会跟随下一次出征。
- 不自动清理不可达页，因为原档备份可能还引用它们。备份/搬迁需复制整个存档目录，包括 ground-loot；不能只复制 save.json。磁盘长期占用优化留待后续基于主/备份/迁移档引用进行回收。
- F9 与普通背包中的快速读取入口默认关闭。仅编辑器正在试玩时，可用 Ball Maze→开发工具→切换 F9 快速读档，显式启用当前会话的开发功能。正式构建始终禁用，包括开发构建；退出后自动恢复、损坏恢复界面的重试按钮不受影响。
- 新增 ForestExploration 枚举值 2，原值 0/1 不变。森林不推进固定波次，不开放 N 下一波，不要求 CountForWave 的敌人数，不限制四个事件或原场地坐标。
- 布局保存逻辑描述与版本、种子、节点/道路/遭遇/资源/出口，读取使用已存描述，不重新抽布局覆盖进度。7 个兴趣点、8 条道路，木石矿资源、近战/远程/精英据点；这是 ForestRuins 中的森林布局测试，未宣称正式森林内容完成。
- 新检查点 entitySchema=1。敌人、资源、事件使用实例内稳定字符串 ID；读取按敌人 ID 匹配，数组重排不会串血量。老档只在迁移入口按历史索引一次性赋予稳定 ID，之后写为 v9；不重建物品来源。
- 森林每个蓝色出口具有 ExtractionPoint 实例，ID、范围、引导时长、位置可配置。实例配置写入检查点，锁定正在使用的出口 ID；所有出口调用同一个 BeginExtraction/LockOutcome/CommitSettlement，没有新奖励入口。
- 据点局部侦测、同组报警、追击范围、脱战返回。返回采用移动，不传送、不恢复血量、不重置掉落标志。运行时将真实碰撞源烘焙成 NavMesh，路径不完整时停下，CharacterController 执行移动；不再用绕障角度当作完整寻路。
- 新局生成最多重试 3 次，仍失败使用已验证 seed=1 布局，并记录警告；备用布局也失败则取消出征，复用原营地恢复逻辑。非法布局故障注入尚未作为通过项。
