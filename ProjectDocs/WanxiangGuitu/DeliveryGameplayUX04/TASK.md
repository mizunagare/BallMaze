# GAMEPLAY-UX-04：交互缺陷修复与弓/法杖设计审计

仓库：`mizunagare/BallMaze`
当前已知 main：`3b14dca0c246abdc71f44c02c765716d989fb6b4`。开工必须重新读取远端完整 SHA；若已前进，审计差异，不 reset、不覆盖工作区。

## 目标与顺序

本批先修四类可复现问题：
1. 攻击范围提示覆盖资源，但实际没有造成伤害，疑似提示几何与真实判定不一致。
2. 制作“白色长剑”多次仍未完成，目标追踪提示、配方列表和制造结果不一致。
3. 制作、仓库等滚动列表选择条目后跳回顶部。
4. 背包/仓库拖放抓取偏移生硬，缺少自动整理与双击转移。

弓蓄力、法杖技能重设计和自动追踪只做设计提案，不在本批直接改伤害、冷却或添加追踪逻辑。人工试玩仍 NOT_RUN，不阻止这些客观缺陷的代码修复。

## 硬性边界

- 不升级 Unity/URP/依赖，不新增 CI。
- 不改 v9 存档合同、经济、掉落概率、随机流、地图布局和结算语义。
- 不修改用户场景、ProjectSettings、未提交修改或真实存档；用隔离工程和合成存档。
- 保留历史 FAIL、NOT_RUN、UNRESOLVED，不覆盖旧汇总。
- 自动化/Editor 输入不冒充原生人工验收。
- 先建立修复前复现与原始数据，再做最小修改。若发现需改存档合同或经济规则，先停止并提交方案。

## GAME04-01：攻击范围提示与实际命中一致

审计 `AdventureCombat.Melee()`、`AdventurePulse.SpawnMelee()`、`AdventureResource.Hit()`、`WeaponHit.Apply()`、`AdventureCombat.Sight()`、资源/敌人的 Collider 层级。

截图中石头被橙色轮廓覆盖，但生命仍为 70/70。不能直接调大半径，必须定位原因。固定角色位置、朝向、武器、攻击 ID、资源稳定 ID与场景，记录：
- 输入、释放帧、提示顶点、Overlap 命中候选与最终过滤原因；
- 玩家攻击起点、目标锚点、Collider bounds、前向 dot、横向偏移；
- Sight Ray 命中顺序及是否被目标自身/子 Collider 误判为遮挡；
- `AdventureResource.Hit()` 是否调用、HP 前后值。

重点检查提示是否从角色根部绘制，而实际命中球心是 `transform.position + Vector3.up`；枪的横向过滤与提示形状是否使用同一原点和同一几何合同。若不一致，提取共享纯函数/几何合同，避免提示和判定各自维护近似公式。目标多 Collider 只能按设计命中一次；墙/地形仍必须正常遮挡。不能从 UI 直接扣血。

验收：距离×角度矩阵覆盖正前、侧向、近/中/远、边界内外、遮挡、多 Collider；提示覆盖与真实命中一致；HP、采集事件和反馈一致；四武器与品质分支回归不退化。除非证据证明必要，不改伤害、冷却、经济、掉落、随机流或 v9 合同。

## GAME04-02：制作目标“白色长剑”闭环

审计 `CraftingTargets.Select/Needs/Compact/Details`、`AdventureRecipes`、`AdventureLoadout.Craft()`、营地制造事务、`Onboarding.Crafted()` 和 HUD/目标提示。区分材料追踪与教程任务，不能只改文案。

记录配方身份、品质、recipe ID、制造入口、材料消耗、产物 ID/位置和存档 revision。明确目标状态：未选择、缺料、材料齐全待回营、可制作、已完成、未解锁、保存失败/待核对。

若这是一次性制作目标，第一次成功制造指定品质/类型后应完成并持久化；若是数量目标，显示明确进度。仅材料齐全不能代表制作完成。“追踪缺口”成功后必须更新 HUD/详情，失败要显示原因；重复选择同一目标不能无意义递增 revision。制造已提交但 UI 回调失败时，以业务提交结果为准，不能重复扣费或发奖。

验收：
- 合成 Profile 选择白色长剑目标，保存并新进程恢复后仍正确追踪；
- 材料齐全时 HUD、配方状态和实际制造入口一致；
- 正常 UI 制作后目标按明确规则完成；再制作第二/第三把不重复推进或奖励；
- 覆盖背包材料、仓库混合、缺料、未解锁、空间不足、保存失败、制造提交后 UI 刷新失败；
- 取消/切换目标后 HUD 正确更新；保留 v9 格式，不擅自新增必需字段。

## GAME04-03：滚动位置保持

审计 `CatInventoryPresenter.LateUpdate()` 的 `stamp/rebuild/Build()` 和 `CatUI.Scroll`。选择条目导致 stamp 变化并重建 UI 时，保存各独立 ScrollRect 的 normalized position/anchored position，并在重建后恢复。

每个列表按页面 ID + 列表 ID + 筛选/分类/搜索状态独立保存：制作配方、背包、仓库装备、仓库材料、待领取、溢出列表不能共享一个全局滚动值。数据变更后把位置 clamp 到合法范围；筛选移除当前条目时使用明确回退策略，不能无故跳顶。滚动恢复不得触发存档写入或 revision 递增。

验收：在中下部连续选择、搜索、筛选、刷新、切页/返回后，视口不跳顶；内容变短不出现 NaN/越界；各列表不互相继承位置。标明 Editor 受控输入与原生操作的证据层级。

## GAME04-04：拖放、自动整理、双击转移

### 抓取点
审计 `ContainerInventoryView.Input/BeginDrag/Ghost/DropOn` 的坐标转换。当前 Ghost 使用固定 mouse 偏移，而放置使用 grab offset，需确认两者是否一致。拖动时被抓取格必须贴合鼠标，旋转后抓取格映射到合法新尺寸；预览与实际放置使用同一目标坐标。禁止“预览可放置、实际事务失败”的坐标偏差。

### 自动整理
为背包和永久仓库提供自动整理；装备盘若排序会改变战术布局，可先不支持并明确说明。只移动现有物品，不复制/销毁/合并物品，不改 ID、品质、词缀、主副武器、穿戴状态和来源账。
- 用确定性排序和摆放算法，优先大件/容器物品，再按稳定 ID；
- 先生成纯内存布局，全部可放入才一次性提交；
- 无解时保留原布局并说明原因；保存失败回滚；
- 保留 `board/worn/overflow/rotation` 语义，不能把溢出或穿戴物品静默放入普通格子。

### 双击转移
营地、数据就绪且无结算门禁时：背包物品双击存入永久仓库，仓库物品双击取回背包。必须走现有仓库存取事务，检查空间、保护物品、携带限制与保存结果。拖动超过阈值不得触发双击；单击仍只选择。冒险中禁止绕过永久仓库规则。失败时两侧容器均不变；结果不确定时进入既有恢复核对流程。

验收：不同尺寸/旋转的抓取坐标一致；自动整理同输入同布局；所有 ID/数量/属性/来源账不变；空间不足、保存失败、重复点击、双击与恢复不丢物、不复制、不重复交易；原拖放、交换、旋转、右键取消回归通过。

## COMBAT-DESIGN：弓蓄力与法杖特色（本批只出设计提案）

新增 `COMBAT_DESIGN_PROPOSALS.md`，分别给出机制、输入状态、取消/暂停、视觉/音频反馈、平衡风险、兼容现有技能和可测验收。不得直接实现新机制。

### 弓
保留现有普通单箭攻击，新增“按住蓄力、松开发射”的候选特殊攻击/瞄准模式。定义最小蓄力、最大蓄力、伤害/穿透/散布变化、移动惩罚、取消与弹药/冷却语义。优先使用现有 Input System 动作映射；必须支持键位重绑定。不能让长按普通攻击意外卡住，也不能让 UI 焦点期间蓄力或误发射。

### 法杖
普通攻击目前明确为单发直击，不冒称 AoE。技能应与普攻形成机制差异，可比较“范围爆裂/地面持续区域/弹射连锁”三种方案，选择一种最适合现有代码和资源的最小方案，明确范围、目标上限、持续时间、命中去重、视觉提示和代价。不得只把普通攻击半径加大后称为新技能。

### 自动追踪被动
只评估为可选装备/品质被动，不默认加给所有远程武器。列出瞄准辅助强度、最大转向角、寻敌距离、遮挡/目标优先级和对玩家瞄准技能的侵蚀风险。先提案，不在本批实现。
