# BALANCE-AI-01：成长节奏、敌人威胁与战斗 AI

仓库：`https://github.com/mizunagare/BallMaze`

## 1. 目标

用户反馈当前经验条过短、升级过快、敌人伤害偏低，敌人 AI 的攻击逻辑缺少威胁感。截图中玩家等级已到 8，生命为 146/150，周围同时存在普通敌、精英/特殊敌与 Boss 类目标，但仅凭截图不能证明具体经验曲线或 AI 行为有缺陷。本批必须先测量实际配置和运行行为，再实施有数据依据的调整。

目标不是简单提高所有怪物 HP/伤害，而是建立合理的成长节奏、敌人威胁梯度与可读、可反制的 AI。难度应来自玩家决策、敌人行为和资源压力，而不只是血量膨胀。

## 3. BAL01-01：经验曲线与升级节奏审计

先输出 `PROGRESSION_BASELINE.md` 与机器可读的经验表，记录：
- 当前等级上限、各等级经验门槛、累计经验、经验条分母/显示规则。
- 普通敌、精英、Boss、资源/事件（若有）各自的实际经验来源与数量。
- 击杀经验是在命中、死亡、结算还是撤离时提交；死亡/放弃/撤离对经验的现有影响。
- 同一敌人是否可能重复发经验，复活/重置/恢复是否重复奖励。
- 经验 HUD 显示的是当前等级内经验、累计经验还是百分比，确保显示与实际升级阈值一致。
- 现有武器、等级和品质对杀敌速度的影响；用固定种子记录实际升级时间和击杀数量。

不要凭“经验条看起来短”直接调 UI 长度。必须区分：
1. 经验阈值确实太低；
2. 敌人经验奖励过高；
3. HUD 进度条比例/文字显示错误；
4. 早期等级成长本来就快，但中后期没有节奏曲线。

### 设计目标（先作为调参假设，测量后确认）
- 初始数级应让玩家较快学会基础成长，但不能在短时间内连续升级到高等级。
- 早期、 中期、后期升级所需累计经验应有清楚的递增趋势。
- 一次普通遭遇不应让玩家无理由连续跳多个等级；Boss/高风险目标可以提供显著成长回报，但不能破坏长期曲线。
- 升级选择/奖励仍按现有合同提交，不能重复发放。
- 不为延长游戏时长而无差别提高所有等级门槛。先给出至少三条候选曲线（保守、中等、偏慢），对同一固定遭遇和预计 Run 长度进行模拟，再选择一条并说明依据。

交付经验曲线表：等级、单级需求、累计需求、预计普通敌击杀数、预计普通 Run 达到等级、Boss 奖励占比。击杀数只能作为估算，必须注明敌人经验和实际战斗差异。

## 4. BAL01-02：敌人威胁基线与数值分层

对普通敌、远程敌、精英、Boss 分别记录：
- 最大生命、攻击伤害、攻击间隔、攻击距离、移动速度、警戒距离。
- 攻击前摇、攻击持续/命中窗口、恢复时间、攻击范围与实际命中规则。
- 玩家防御、闪避无敌/减伤、受击硬直、药水治疗量与冷却。
- 同一等级/装备下，敌人一击造成的生命百分比、连续两次受击的存活率、单个敌人击杀时间和玩家受到的伤害。
- 敌人是否能在攻击前给出可读预警，玩家是否有可行的闪避/走位窗口。

必须建立敌人威胁梯度：
- 普通近战敌：能施加压力，但不应靠无法反应的高伤害秒杀。
- 远程/控制型敌（若存在）：通过站位、投射物或区域限制迫使移动，攻击应有可读的发射/命中逻辑。
- 精英：至少有一项明确行为或攻击节奏差异，不能只是普通敌堆血。
- Boss：有明确阶段/招式变化、较强攻击信号和惩罚窗口，不应仅靠提高 HP/伤害。

如果现有敌人类型不足以形成上述梯度，本批只提交内容设计提案，不直接增加新敌种。

## 5. BAL01-03：AI 行为审计与有限增强

先绘制每类敌人的状态图，按实际代码填写，不假设已有功能：
Idle/Patrol → Detect → Approach/Reposition → Telegraph → Attack/Projectile → Recovery → Reassess/Chase → Leash/Return → Dead。

检查：
- 发现目标的距离、视线、丢失目标和追击边界。
- 近战敌是否会停在有效距离、转向玩家、明确预警、执行攻击并进入恢复，而不是贴身后无反馈地连续扣血。
- 远程敌是否检查射线/遮挡、合理选择发射时机，并避免投射物穿墙或生成后瞬间命中。
- 多敌协同时是否避免完全同步出招造成无法反应的伤害叠加；可用轻量攻击排队/冷却错峰，不构建复杂群体 AI 框架。
- 玩家闪避、距离拉开、绕障碍、暂停、死亡、换场景时 AI 状态是否正确取消/恢复。
- Boss 与普通敌是否共享错误状态或在重置/恢复后遗留攻击。
- AI 是否只在允许的视线/范围内知道玩家位置，避免无视遮挡、全地图追踪或作弊式锁定。
- 受击、死亡、攻击取消、场景卸载时清理预警与投射物。

### 允许的最小增强
只在基线证据明确指出缺陷时实施：
- 明确的预警/攻击/恢复状态，确保伤害只在有效命中窗口发生。
- 目标转向与攻击方向一致，修复“看向玩家但攻击判定朝另一个方向”等问题。
- 合理追击/丢失目标/返回区域边界。
- 轻量的多敌出招错峰或攻击冷却，避免所有敌人同时无解连击。
- 投射物速度、遮挡与命中时机的正确性修复。
- 普通、精英、Boss 使用已有配置形成不同节奏；不凭空增加复杂状态树。

不允许：
- 只靠提高敌人 HP/伤害掩盖 AI 缺陷。
- 让敌人无前摇瞬间攻击、穿墙、超出范围命中、无视闪避/暂停。
- 把敌人攻击伤害提升到玩家没有合理反应机会的秒杀水平。
- 在没有设计批准时新增敌种、技能树、动态难度系统或新存档字段。

## 6. BAL01-04：平衡试验矩阵

先冻结当前基线，再做有限对照。至少包括：
- 3 个固定种子；每个种子至少 3 次独立进程或可证明独立的 Run。
- 低/中等级角色；至少两种装备防御水平；固定武器与药水条件。
- 普通敌、远程敌（若存在）、精英、Boss 的单体战与混合遭遇。
- 玩家原地攻击、正常走位、正确闪避、错误时机闪避、被多敌夹击。
- 每个遭遇记录：击杀时间、玩家受伤、治疗次数、闪避次数、攻击被闪避/未命中次数、敌人攻击命中率、升级次数、经验来源账。
- 对比修复前后同一输入；随机结果必须记录 seed/stream，不能只比较平均值而丢弃离群失败。
- 若 AI 测试驱动会直接发起攻击或 teleport，必须明确标为受控规则测试，不冒充正常 AI 实战。

### 建议的指标（不直接作为最终玩家平衡结论）
- 普通遭遇应能造成可观察的生命/资源压力，但不应稳定地无伤或稳定地秒杀玩家。
- 普通敌攻击必须存在可观察的预警与反应窗口。
- 精英/Boss 的难度应主要体现在招式、位置压力和阶段，而不是只把生命放大。
- 升级节奏应与预期 Run 时长匹配，不在开局极短时间内连续跨越多个等级，也不能让整个 Run 无成长反馈。
- 所有指标先给出现状值和分布，再根据产品目标选择目标区间；不得先编造目标再宣称达标。
