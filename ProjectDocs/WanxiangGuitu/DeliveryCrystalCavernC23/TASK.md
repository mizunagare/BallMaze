# CP06-C2.3：地下湖与环湖探索

## 一、任务目标与版本

仓库：mizunagare/BallMaze

产品基准：`35efda203b0b36801139fa2cc80ab7ba895207af`

来源分支：`feature/cp06-crystal-cavern-c22`

新建独立分支：`feature/cp06-crystal-cavern-c23`

本轮在已交付的 C2.2 上新增地下湖、两条环湖路线和回程捷径。形成“探索到达湖岸—选择路线—取得普通资源—开启捷径—回到入口—正常撤离”的可玩流程。本轮不实现洞窟 Boss、不新增武器技能、不新增永久特殊奖励，不重新开发隐藏矿室或晶核精英。

开工时读取远端并确认基准可用、记录实际 HEAD 及用户工作区状态。禁止覆盖用户修改、强制重置旧分支或合并 main。若分支名已有内容，先核对现有任务状态，禁止覆盖或重复实施已完成部分。本文是实施任务，不表示代码已经执行。

## 二、范围与推进方式

先提交或记录兼容映射、布局和受影响文件，再依次完成白盒通行、交互与存档、场景表现和验证。这些属于同一次已安排的实施，不必每完成一个小步骤都停止等待再次授权。

本批只增加一个主要区域：地下湖。现有入口、矿脉区、能量通道和隐藏矿室保持可用；湖区从能量通道末端自然延伸。禁止同时扩展完整 Boss 大厅、城镇或全新成长系统。

## 三、地下湖布局与路线选择

设置湖岸入口、对岸观察点、两条实际可走的路线及回程捷径。两条路线在同一地图内连通，不能通过传送或仅切换场景代替空间连接。

外环岩岸为较长、低风险路线，有足够肩后镜头空间。内环石径相对较短，安排适量已有巡守或晶核精英，使玩家通过战斗或走位换取通行效率。首版不设置必须跳跃、游泳或指定武器才能通过的主路线。

两条路线通往同一对岸区域，不以不透明的隐藏门槛强制玩家战斗。玩家可放弃探索，沿已验证的道路返回入口免费撤离。高风险路线不是无预警必伤路线，也不允许敌人在狭窄边缘永久封死唯一退路。

对岸设置普通供能机关，开启一条此前关闭的回程石桥或岩廊。优先启用已有固定桥面和关联碰撞，不做复杂运动平台。机关无需新增材料扣费；开启反馈明确，开启后实际双向通行和导航可达。捷径是本 Run 的状态，不是永久角色解锁。

不要仅靠扩大现有长方形房间、换色或堆放晶簇交付地下湖。白盒可使用基础几何体；最终原型至少要有可辨识湖岸轮廓、高低岩层、对岸地标和路线层次。

## 四、水体与空间表现

优先复用现有合法水体、岩石和晶体资源；必要时以自有网格和现有可用材质制作。记录真实来源与资源缺口，不购买插件、大型素材包或引入未经许可素材。

本轮不做游泳、潜水、溺水、浮力和水下战斗。深水为明确不可通行区域，用可见岸壁、落差或护栏配合真实碰撞限定边界；NavMesh 不得覆盖深水。不要在整片湖面铺设可行走碰撞使角色在水上行走，也不要在视觉上能通过的岸边设置难以理解的隐形墙。浅滩仅在实际具有可行走地面时开放。

固定资源在编辑器阶段制作并保存。运行时加载版本对应的场景资源，不依赖 MapMagic 或其他 Editor 程序集进行湖区生成。

湖面、雾和晶体亮度不能遮住地面攻击预警、敌人轮廓和撤离提示。优先复用已有渲染能力，不修改全局 URP、GraphicsSettings、后处理或用户图形配置。新增效果必须有真实 Player 支持检查；历史曝光测试 PASS 不覆盖新效果。效果不可用时保留可用的简单表现，并如实记录缺口。

## 五、遭遇与战斗保护

复用现有巡守和晶核精英，不修改其旧配置、既有伤害、阶段时长或七种武器数值。若新布局确需不同遭遇参数，限于新版本遭遇配置并独立列明，不覆盖旧 Run 参数。

保证七种武器能在实际战斗区域释放和命中，墙体、晶柱、岸壁继续阻挡攻击。不能为了展示湖区效果关闭碰撞、允许远程穿墙或强制镜头转向。

新区域的连续验收流程中，参与遭遇的敌人保持正常 AI，不冻结敌人、清空血量、注入 Damage、传送穿越路线或恢复玩家生命来完成测试。允许在测试开始前建立清楚标识的合成存档和装备夹具。专项受控命中试验与完整遭遇流程必须分别记录。

已有近距预警遮挡是待体验项。C2.3 优先通过新区域宽度、掩体位置和战斗点选择改善可读性，不擅自改 CP05 镜头或全局 EnemyAttackSignal。需要共享表现代码修改时另列最小方案，不在地图批次顺带重写。

## 六、普通奖励及结算

只使用既有铁矿、晶石及普通装备奖励路径。每类新增资源节点、普通宝箱和遭遇数量先在布局中列明，注明额外资源供给，不宣称新增地图收益对经济完全没有影响。

同一 Run 同一来源只处理一次采集、死亡或领取；新 Run 可以再次获得普通奖励。本轮不新增 SpecialRewardId、材料枚举、配方、货币或永久首奖。

环境摆放、湖面动画、装饰和路线选择不能消耗奖励随机流。旧 C2.1、C2.2、森林和遗迹在相同合法操作下的既有奖励规则不变。C2.3 的新增奖励通过其本 Run 已有权威来源账和可恢复随机路径生成，不另造未经审计的奖励入口。

验证必须覆盖地面物品、已拾取库存、待结算、已提交及永久仓库之间的区别。重复拾取、重复结算和读档不得增加同一批物资。

## 八、机关、导航和恢复

捷径状态与实体碰撞、门/桥表现和导航一致。开启失败或导航重建失败时，应保持可重试、可返回的状态，不能出现“记录已开而桥未可走”或“桥可走但存档仍未开”。沿用现有安全处理，不为本批重写整个导航系统。

至少覆盖关闭状态保存、开启后保存、奖励落地未拾取、奖励已拾取和正常撤离后的恢复。加载时先恢复正确版本与机关状态，再完成必要导航和可达性检查。

旧能量区读取后从安全恢复窗开始的规则保持不变，不擅自改为精确恢复危险相位。新区域不增加靠反复重载获得额外物资或重复精英掉落的路径。

## 九、验证矩阵

Editor 和非开发测试 Player 分别执行受影响流程，不继承旧 PASS 作为本轮实测。

| 组别 | 必须提供的证据 |

| 两条环湖路线 | 实际移动、双向通行、碰撞、导航，以及回到入口的合法路线 |
| 捷径机关 | 关闭阻挡、合法交互、开启反馈、双向通行、重复操作不重复执行 |
| 水体边界 | 深水不可行走、实际岸壁碰撞、敌人导航不穿深水、不从岸边卡死 |
| 正常遭遇 | 参与遭遇的 AI 正常运行，真实攻击、命中、规避与退出战斗；不得冒充人工体验 |
| 七武器 | 新区域中的普攻和默认技能真实命中与遮挡；受控用例与完整战斗分列 |
| 奖励及恢复 | 同一 Run/来源身份、节点和宝箱状态、掉落身份与必要属性、库存与结算差额 |
| 旧档兼容 | C2.1/C2.2 原资源和状态恢复，受影响森林/C1 入口与保存路径定向检查 |
| 发行与表现 | 新资源实际加载、非开发 Player 画面、纯包无驱动、诊断关闭及启动退出 |

至少保留一条连续的受控自动化流程：营地出征—经过原有区域—环湖探索—普通奖励获取—开启捷径—正常回程撤离—新进程核对入仓。测试开始后不传送、不改血、不跳过业务结算。无需把每条武器专项用例都扩展成一遍全地图通关。

涉及精英落地奖励恢复时，增加同一批奖励 ID、类型、数量及适用装备属性的逐项对照，不能只比较物品总数。已有测试覆盖到哪一层就写到哪一层，不扩大结论。

对无法执行的项标记 NOT_RUN，缺少可判定证据的项标记 UNRESOLVED。保留所有首轮失败，不用重试覆盖原判定。既有历史失败与本批最终运行统计分列。
