## 2. L1 · 14 项扩展技能的收益与代价规格

### 2.1 目标带与验收式

定义见 `CALC_MODEL.md`：`B = D/(R×W)`（窗口内爆发）、`η = 1+(B−1)×W/C`（相对纯普攻的持续效率）。
**恒等式 `η = 1 + (B−1)×W/C` 决定了：B<1 时改冷却只会更糟，必须先修 W 或 D。**

| 带 | 门槛 | 项数 |
|---|---|---|
| T1 无独占机制 | `B ≥ 1.10` 且 `η ≥ 1.01` | 1（`sword.triple`） |
| T2 有独占机制 | `B ≥ 1.00` 且 `η ≥ 1.00` + 至少一个场景优于槽 0 | 11 |
| T3 条件/纯控制 | **η 不适用**，另设口径 | 2（`twin.counter`、`sc.pull`） |

**不追平槽 0 倍率。** 槽 0 的 `W/C ≈ 0.071`，扩展技能 `W/C ≈ 0.05–0.19`；且槽 0 吃品质、扩展技能不吃（`CALC_MODEL.md §5.3`）。红弓 `bow.rain` 的 η=1.700 是品质体系的结果，压低它会连带改 4 把旧武器的品质专属，超出本批范围。扩展技能的定位是「在独占场景里替代槽 0」，不是「倍率追平槽 0」。

| 类别 | 现在 +25% 伤害 | 现在 +1s 冷却 | E-A 后 +1s 冷却 |
|---|---|---|---|
| 普攻 ×7 | 否 | 否 | 否 |

**必须在实现批同时把 §2 提案与 E-A 合并计算**，因为两者都改冷却；`build_balance_model.py` 已内置该叠加口径。

## 5. L1/L4 · 双刃 / 巨剑 / 镰刀品质专属效果提案

### 5.1 现状与提案原则

**[源]** `WeaponTraits.Exclusive`（`:10`）对三把新武器统一返回「独立武器机制 · 通用词缀按实际命中结算；技能见当前武器说明」，**无任何品质专属**。而 4 把旧武器从紫起就有剑气 / 穿刺余波 / 侧球 / 加箭。
**[推]** 这是 `CALC_MODEL.md §5.3` 的品质断层在三把新武器上的镜像：它们连「槽 0 吃品质」都没有。

**提案原则**：
1. **只复用已存在的参数族**：段数、半径、距离、时长、倍率、追加一次同类型判定 —— 与旧武器「加箭/加剑气/加侧球」同构；
2. **不新增技能、词缀、武器、货币、强化/重铸/升星**；
3. **不改控制免疫**（Boss 仍免疫破防/牵引）；
4. **紫/金/红三档各自只改一个参数**，便于 Player 逐档验收；
5. 标注哪几条需要 L2 授权，不混入默认包。

### 5.2 九条提案

## 9. D-24「30% 备用武器」对照分析（只读，不实施）

**[源]** 现状 `AdventureLoadout.cs:22`：`Attack = Active.Sum(i => i.Attack) + 胸挂/背包 attackBonus`，`Active` 含所有 `board` 装备与 `Main`（`:19`）。
**[推]** 假设把「非主武器的武器」按 30% 计入（D-24 选项 B），计算对 `P = 25 + Attack` 与击杀时间的影响：

| 盘面（Main 为第一件） | 现状 P | 30% 规则 P | ΔP | TTK 倍率 |
|---|---|---|---|---|
| 紫弓 43 + 绿枪 19 + 白剑 8 | 95.0 | 76.1 | −19.9% | ×1.248 |
| 红 132 + 紫 43 + 绿 19 | 219.0 | 175.6 | −19.8% | ×1.247 |
| 三件红 132×3 | 421.0 | 236.2 | −43.9% | ×1.782 |

**三条结论**：
1. D-24 **只缩放 P**，不改 `D/W/C/R` 的比值结构 —— 因此 **η 与 B 完全不变**，无法解决「扩展技能没人用」；
2. 它改变的是**绝对击杀时间**（+25% ~ +78%），会直接影响 P1C 三条已通过的「击杀→撤离」闭环预算；
3. 它与「多带武器」的现有 UI 表达冲突，但没有 Player 证据说明玩家真的在堆盘内武器。

**故本规格只做对照，不提案、不改代码。** 若未来授权 D-24，必须与 §2 的数值包**同一批**验证，否则两套改动会互相掩盖。
