# 存档 v9：分页掉落与稳定森林实体

保留 v1～v8 的读取与来源迁移。v8 读取时先建立原文 save-v8-before-v9.json，成功恢复后立即保存 v9；失败冻结并保留原档。v7 保留原来的 UpgradeV7，再保存 v9；v1～v6 原有 Normalize/AdoptLegacy/迁移保护路径不删。旧存档的永久仓库、配方、装备 ID、来源账、清单和布局不清空。旧 Run 不改变模式或猜测来源。

v9 主封装仍统一保存 ProfileState、RunState、SettlementRecord，原唯一结算日志与修订号、SHA256、备份、Flush(true)/File.Replace 保持。新增地面掉落页是不可变世界记录，不是第二个独立奖励/永久状态文件。

保存顺序：完整验证内存快照→克隆快照→按 256 条写 ground-loot/<SHA256>.json 页→克隆快照用页引用替代内联掉落→主文件临时写入并 Flush(true)→原子发布。发布失败前的额外页只占空间，不会发奖或扣物。读取按清单校验并展开所有页，再使用原校验器和恢复流程；缺失/篡改页面不能按空掉落继续。

注意：备份整个存档目录。新格式不能由旧版本程序读取，回退程序时使用迁移前原文备份，勿把 v9 伪装为 v8。页自动回收暂未启用，避免删除备份引用的物资；需关注长期磁盘增长。主元数据 8 MiB 的写入/读取上限一致，达到限制会明确失败并保留已有档，未静默丢物。

新增世界字段：entitySchema、forestWorld、ForestLayout、GroundLootPage[]；敌人/资源/事件 entityId；敌人据点 AI 阶段；Run.exitId。forestWorld 显式区分世界类型，避免 JsonUtility 对 null 嵌套对象创建默认实例时误判森林。迁移旧索引只做一次 ID 映射，v9 缺失 ID 不再猜测补回。

迁移样本均为隔离测试档：v1～v6 是有版本字段依据的合成历史样本；v7/v8 是前批测试运行产物，未使用玩家真实存档。v8 覆盖营地、在途、待提交、已提交四种状态。
