## v7 → v8

读取完整校验有效的 v7 后，先逐字节保存 `save-v7-before-pve-v8.json`。保留原 ProfileId、RunId、实例 ID、入场快照、材料/药水来源账、仓库、配方和结算。

v7 已经能证明来源：清单内实例标为 DeploymentProtected（遗留保护 Run 则 LegacyProtected）；其余当前随身物品标为 RunLoot。不会把 v7 的新战利品全部升级为保护物。未进入背包的地面装备在真正拾取时登记来源。

旧在途补给超过新默认上限时，本局容量取“6 与迁移时实际堆栈数的较大值”，数量不扣，后续不因拾取持续扩容。营地超限物资仍保留，下一次出征前可存入仓库；不会自动丢弃。v8 重复读取不再重算迁移或容量。

成功写出完整 v8 后才结束迁移。失败显示恢复提示并停止覆盖；修复目录/定义后重试读取原档。已有 v7 Pending/Committed 的四类运行时样例已分别验证。

## v1～v6 → v8

沿用原 v1～v6 兼容链、旧剑甲/材料/容器/双武器/仓库/配方映射与归一化；新增原字节档案 `save-vN-before-pve-v8.json`。为兼容原工具，既有 `before-adventure-v7 / before-containers / before-camp / before-workbench` 档案名称也继续保留，不代表中途降级写盘。

来源不明的旧在途物资只在迁移时建立一次 LegacyProtected 基准；不追溯惩罚、不虚构入场词缀、不发胜利/徽章。迁移后新取得的物资仍有风险，消耗仍先花本局部分，再花旧带入剩余。旧档已有合法装备/配方权益按原链保留，现代新拾取不提前补解锁。

已知非法格子位置/重叠进入可见迁移暂存；缺失随身/仓库模板实例保留原 ID 和数据到持久待领取，补回模板前不能领取，或明确确认弃置。其余必要定义/结构不合法会冻结并提示恢复，原文件不清空。不会把异常数据静默当新档。

## 错误恢复和回滚

- 主档损坏尝试完整备份；两者都坏则停止游戏与自动覆盖，显示重试入口，修复后可读取。
- 终局/结算存档不拆写：Pending、Committed 与 Profile/Run 同边界。崩溃恢复不重复发物，不用健康旧世界撤销已保存死亡。
- 出征保存/初始化失败回营；若回营恢复也失败，则冻结并禁止保存半恢复状态，保留原营地文件等待重读。
- 结算已提交但营地装载失败，保留 Committed 和收益计划，再次读取/确认只恢复营地，不重新发奖。
- 旧代码无法读 v8。确需降级时，先关闭程序并另备份完整玩家目录，再同时恢复对应代码和对应迁移前档案。旧档案不包含迁移后的收益；本批不自动降级或承诺无损回滚。
