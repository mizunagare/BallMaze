# WanxiangGuitu PLAYER-01：独立 Player 冒险纵切验收任务书

## 1. 批次目的

批次：`PLAYER-01`

开始基线（远端 `main`）：`3839d4f581415f20251737bba5cc1c5a4afa56ff`

BUILD-01 的限定复审结论：短路径验证工具修复有效；它不是对 Unity/URP 导入器的产品修复。当前两份短根工程报告为 `0 Error / 91 Warning / 4 Log`。91 条警告仍开放。

本轮不新增玩法。使用短路径隔离根，将正式非开发 Player 的构建、标题入口、实际游戏业务闭环与新进程恢复形成一条可审计纵切。复用现有代码与 Gather 正常 AI 流程；不重写存档、结算、输入或经济系统。完成后暂停，等待独立复审。

## 4. 具体验收基线

### P01-01：正式非开发构建与产物身份

- 使用 BUILD-01 的短根策略，通过现有 `WanxiangBuild` 入口执行 `BuildOptions.None` 构建。
- 检查完整 BuildReport，不只看 Unity 退出码或 `BuildReport.Succeeded`。
- 记录 EXE、`UnityPlayer.dll`、`Assembly-CSharp.dll` 的 SHA-256、大小及可用的 MVID/程序集身份。
- 检查正式程序集不含 Editor 注入测试类、诊断类或测试专用入口。
- 将 91 条历史警告分类为仍存在、已消失、Editor/导入诊断或可能影响 Player；本轮不得为了减少数字顺带修改无关产品代码。

通过条件：构建输入与产物身份可追溯，完整消息已检查，BUILD-01 的目标路径错误未复现。若仍有 Error，标记 `FAIL` 或 `UNRESOLVED`；不能因进程退出码 0 而通过。

### P01-02：正式 Player 标题与设置

在正式非开发 Player 中验证：

1. 缺少存档时进入标题，不自动创建 Run。
2. 存在合法继续档时显示正确的继续状态。
3. 继续/读取恢复正确的 Profile、Run、区域与存档身份。
4. 新游戏确认期间存档变化会导致确认被拒绝，不覆盖原档。
5. 标题设置入口可以打开操作/键位面板；取消不改变有效设置。
6. 应用有效键位后重启 Player，键位和其他偏好保持一致。
7. 记录真实退出方式、退出码与存档指纹。

后台 `WM_CLOSE` 只证明该关闭路径，不是物理标题栏点击。无法安全执行物理输入时，原生输入项必须标记 `NOT_RUN`。

### P01-03：正式 Player 的完整搜打撤纵切

复用现有 Gather 正常 AI 策略及正式业务入口，尝试完整执行：

标题 → 进入/继续合成档 → 森林探索 → 实际采集 → 验证物资 → 修复渡口（路线要求时）→ 合法撤离 → 结算提交 → 回营核对永久仓库 → 取材制造 → 再次出征 → 新进程恢复。

每个阶段记录：
- Profile、Run、区域、种子、布局修订与装备身份。
- 前后库存、来源账、出口回执、结算状态与随机流状态。
- 实际执行的进程、命令、退出码、日志与状态快照。
- 失败、未知结局与技术中断；不得将技术中断算作死亡，也不得静默丢弃尝试。

必须通过真实正式业务代码完成采集、扣费、撤离、结算、入仓和制造。不得直接改 JSON、注入最终状态或用测试替身伪造成功。新进程恢复必须启动新进程，不能将同一进程重新读 JSON 冒充跨进程恢复。

若当前正常 AI 流程依赖 Editor 专用命令或测试注入，必须将该环节标记为未通过，不得宣称正式 Player 完整闭环通过。

### P01-04：正式 Player 中的键位消费

复用 INPUT-01，不重做键位系统。

- 在正式 Player 修改一个安全测试键位、应用、重启并核对持久化。
- 进入合成档，验证对应实际行为与提示文案使用同一有效绑定。
- 检查保留键语义（Esc、鼠标右键、F2/F3/F5/F9、1/2/3、N）没有被改绑破坏。
- 若通过虚拟 InputSystem 事件验证，明确标注“正式 Player 内虚拟输入”，不得称原生键鼠或人工验收。

### P01-05：失败恢复与存档保护

至少验证：
- 坏档/不可继续档不会被自动覆盖。
- 新游戏确认期间存档变化会被拒绝。
- 保存失败、结算未提交、结算已提交后进程退出有不同处理。
- 已提交结算在新进程恢复后不重复发奖。
- 测试仅使用隔离合成数据，真实玩家目录未被访问或修改。

复用已有可靠的受控测试可以，但必须区分“本轮新执行证据”与“历史证据”。

### P01-06：原生与人工验收边界

只在明确授权且不会抢占用户桌面的独立 Windows 环境中执行物理键鼠和独立人工试玩。记录环境、分辨率、设备、步骤与原始证据。若无授权环境，U16 与人工试玩标记 `NOT_RUN`，说明缺失条件；不得用虚拟输入、截图或 NPC 替代。

### P01-07：性能基线准备

本轮不要求无依据地承诺目标帧率，也不要求立即优化。若存在安全隔离的正式 Player 运行环境，记录固定场景、分辨率、画质、硬件、CPU/GPU 帧时间、内存/显存、加载耗时及采样方法；没有合适环境则标记 `NOT_RUN`。不得把一次启动或静态截图称为性能基准。

## 5. 本轮范围控制

本批以验收和诊断为主。除非正式 Player 运行暴露可复现的阻断缺陷，否则不要修改产品玩法代码。

如果发现产品缺陷：
1. 先保存复现输入、原始日志和失败结果。
2. 判断是否属于本轮范围；超出范围的缺陷只记录，不顺带修复。
3. 对范围内的最小修复建立新测试根，运行直接受影响回归和必要的正式构建。
4. 不通过过滤日志、删测试、放宽断言、改错误等级或更换输入来制造通过。
