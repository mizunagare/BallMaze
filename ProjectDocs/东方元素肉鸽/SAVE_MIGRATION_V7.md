# 存档迁移 v7

## 格式

旧版本 1～6 的读取与原迁移链保留；下一版本为 7。单文件 SaveEnvelope 包含版本、时间、SHA256 校验与修订号；载荷包含 ProfileState、可选 RunState、可选 SettlementRecord。显式存在标记避免 Unity JsonUtility 将 null 管理对象反序列化为默认对象而误认活动 Run。

Windows 玩家目录仍为 `Application.persistentDataPath/ForestRuins`。没有变更公司/产品名或替换玩家真实存档。测试根目录为 `C:/Users/guan/Documents/unitytest/T06Validation`。

## 迁移映射

| 旧格式 | 归一化行为 |
| --- | --- |
| v1 | 沿用旧等级/技能/材料/波次恢复；旧剑甲迁移到装备实例，创建既有容器默认布局 |
| v2 | 保留已有实例 ID 与布局，沿用原容器升级路径和固有数值兼容 |
| v3 | 保留容器 ID、掩码布局、旋转、实例固有数值，不重新掷词缀 |
| v4 | 保留两武器槽、词缀和技能/攻击/切换/翻滚冷却 |
| v5 | 在上述基础上恢复永久仓库/六材料，沿用已有装备补解锁配方策略 |
| v6 | 完整保留永久配方 ID/前置链、仓库、实例与当前世界 |
| 归一化旧模型 → v7 | 仓库/配方进入 Profile；进行中世界进入 LegacyProtected 无尽 Run；未知来源的既有随身物资全量作为保护基准 |

v1、v2 不存在后来版本的全部字段；按旧实现支持的原始语义迁移，不声称保留不存在的历史词缀/ID。v1 需要生成实例 ID 后即保存 v7，再次读取不会再次生成。

## 一次性迁移保护

旧档不能证明来源，不追溯扣除。迁移时已有的随身装备、材料、药水作为当前遗留 Run 的保护基准。已有等级/波次继续，首次结算按新成功/失败规则清除临时成长。迁移后新得的装备和材料没有这层保护；已花的材料/药水仍不返还。

不授胜利、森林徽章或区域资格。首次结算后下一次出征建立正常入场清单，不再使用 LegacyProtected。HUD 和结算会显示迁移保护。

## 备份、异常和重试

1. 先读取封装并验证校验和。旧档在归一化/迁移前复制原字节至 `save-vN-before-adventure-v7.json`；既有 `before-containers / before-camp / before-workbench` 档案继续保留。
2. 不合法的已知物品格子位置/重叠移入可见“迁移暂存”，实例不删；归还后仍可见，整理前不允许新出征。
3. 缺失随身或仓库物品/容器模板的实例保留原 ID/原数据到“待领取”，来源明确标注迁移恢复。模板补回前不可领取，只能保留或明确确认弃置。缺失穿戴容器时提供基础恢复容器承载有效实例，并阻止新出征直到恢复项处理。
4. 不支持的结构、缺失其他必要定义或仍不合法的数据：拒绝恢复、保留原档与档案，禁止自动覆盖，不清空后伪装迁移成功。未知地面掉落模板属于此类，需要补回定义再读。
5. 成功写出 v7 后，再读同一 RunId、同一实例 ID，不重新迁移、不补发物品。
6. 写盘失败保留原档；迁移状态冻结并提示修复存储后重读。新版本不能由旧版本程序读回，勿用旧程序覆盖 v7。
7. 主档损坏会尝试完整备份；两者都不可用则明确阻止覆盖。不要只拷贝 Profile 或 Run 一半。结算日志确保正常提交后的备份至少包含已锁定的终局，不以健康旧世界撤销死亡。

## 回滚方式

代码替换前备份在 `C:/Users/guan/Documents/unitytest/T06ChangeBackup`。如确需回到旧程序，关闭 Unity/游戏后先另外备份完整玩家目录，再使用对应 `save-vN-before-adventure-v7.json`，同时恢复对应代码版本。旧格式备份表示迁移前进度，不含迁移后的新收益；不自动执行回滚，不将其描述为无损降级。

## 测试样例来源

`T06Validation/fixtures/v1.json`～`v6.json` 来自此前各批独立验证工具产生的人工/运行时合成样例，不是用户真实历史档。逐版本断言其本身已存在的数量、ID、固有属性、词缀、布局、配方、材料和波次；无法据此承诺覆盖所有用户自定义/手改的历史档案。异常模板与非法布局样例由 v6 测试档另行构造，原字节备份断言通过。
