## 2. 顺序依赖图

```
UX-03 (A + B-1)  ──┬──> UX-04 (B-2 + D-24)  ──> UX-05 (v10/v11) ──> UX-06 (C)
                   │                                  ▲
                   └── D-24 若选 B 必须与 UX-03 同批 ──┘
```

**[推]** 三条硬约束：

1. **D-24 与 UX-03 同批**，否则「鼓励多带武器」会把「换武器有意义」抵消掉；
2. **UX-05 必须晚于 UX-03/04**，因为持久化字段要记录的是「已经调平衡后的槽位」，先存后调会产生无效存档；
3. **UX-06 必须晚于 UX-05**，因为它需要「地区次数」这类只读字段。

## 3. 每批的验收基线（统一口径）

| 项 | 要求 |
|---|---|
| 真实 Player | 每条 Run 必须 `PLAYER_RUN_COMPLETED`（`exitCode=0`、`complete.txt=PASS`），禁用 Editor/模型代替 |
| 驱动同一性 | 同一批内所有 Run 的驱动 DLL SHA 必须逐字节相同（`build_driver.py -deterministic`） |
| 构建身份 | 记录 `Assembly-CSharp.dll` SHA、EXE SHA、PID、Run ID、命令行与原始日志 |
| 失败留档 | 任何 FAIL 不得改写为 PASS；中间批次进 `Evidence/Player/_attempts/` |
| 保护边界 | 受保护文件 vs 基线逐一对齐（`PROTECTION_HASHES.tsv`，`identical=YES`） |
| 禁令复核 | 驱动内不得出现 `RestorePosition`/`Respawn`/`Heal`/直写血量/直写目标账本（逐条 grep 可复核） |
| 存档 | 未授权则 v9/v10 零改动；授权后需 v9 → 新版本单向兼容证明 |

## 4. 明确不做（本路线图范围外）

| 项 | 原因 |
|---|---|
| 新增武器 / 新增技能 / 新增词缀 | 本批禁令；D-22 只给出「后续允许的边界」 |
| 强化 / 重铸 / 升星 / 单件升级 | D-10 已判「不做」 |
| 持久等级（含换名的「熟练度收益」） | D-06 已判「不做」；D-23 若选 B 需重开 |
| 新地区 / 新首领 / 新矿脉 | D-12 已判「不补遗迹矿脉」；无授权 |
| 难度档 | D-13 当前只给文案 |
| 修改随机流 / 掉落率 / 宝箱概率 / RouteScoring 权重 | 本批禁令，且会破坏 P1C 已通过的闭环可复现性 |

## 5. 风险登记

| 风险 | 触发条件 | 缓解 |
|---|---|---|
| 调平衡后 P1C 闭环退化 | UX-03 改了技能冷却/倍率，导致「击杀 → 撤离」预算不足 | UX-03 必须包含 3 条 P1C 回归 Run，退化即回滚 |
| v10 迁移破坏现有存档 | UX-05 新增字段无「缺失即默认」路径 | 每个字段必须有默认值分支 + 旧档读入测试 |
| 「只展示」被做成「隐性数值」 | D-23 选 A 后实现时偷偷加收益 | 验收时 grep 新增字段的读取点，只允许出现在 UI |
| 证据通胀 | 每批都堆 Run 数量但不增加信息 | 每批强制写「这批证明了什么是上一批证明不了的」 |
| 驱动漂移 | 各批各改驱动导致 SHA 不同、无法横向比较 | 每批只允许一个驱动版本，变更需在报告里列 diff |

---

## 6. 本文件不做的

- 不排期、不给工时；
- 不承诺批次一定按 UX-03 → 06 全部执行（任一批验收不过即停）；
- 不预判决策结果。
