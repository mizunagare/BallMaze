# 装备、词缀与制造成长：缺口审计（WP02-03）

基线 `design/ux-progression-02` ← `verify/ux-progression-01-p1c` @ `4550348f`
标注：**[源]** 源码事实｜**[证]** 交付证据｜**[推]** 设计推论｜**[疑]** 待验证

本文件只做诊断，不提任何「强化 / 重铸 / 升星 / 单件升级」方案——§5 明确禁止先加系统再谈必要性。

## 1. 现有装备空间的实际形状

| 维度 | 事实 | 出处 |
|---|---|---|
| 装备位 | 6 类：武器（主/备）、护甲、长裤、护臂、战靴、饰品，外加胸挂与背包 | `AdventureItems.cs:5` |
| 攻击贡献 | 盘内所有装备的 `Attack` 相加 + 胸挂/背包 `attackBonus` | `AdventureLoadout.cs:19-22` |
| 防御贡献 | 仅「盘内且 board」的装备 `Defense` 相加 | `AdventureLoadout.cs:23` |
| 单件攻击 | `Power × attackFactor`：武器 1.0、护臂 0.35、饰品 0.5、其余 0 | `ItemData/*.asset`；`AdventureItems.cs:52` |
| 单件防御 | 护甲 0.4、长裤 0.3、护臂/战靴/饰品 0.2 | 同上 |
| 品质战力 | 白 8 / 绿 19 / 紫 43 / 金 78 / 红 132（Power） | `QualityData/*.asset` |
| 格位成本 | **武器尺寸按类型固定**（长剑 1×3、长枪/法杖 1×4、弓 2×3、双刃 2×3、巨剑 2×4、镰刀 3×4），**不随品质变化** | `GearItem.BaseSize`（`AdventureItems.cs:27`）；`ItemData/*.asset` 的 width/height |

**[推] 关键推论**：因为尺寸由类型决定而不是由品质决定，**高品质没有任何格位代价**。这一条直接决定了下面 G1 的结论。

## 2. 分类：哪些是数值、哪些是机制

| 类别 | 现有内容 | 数量 |
|---|---|---|
| 纯数值 | 5 个品质档的 Attack/Defense；护甲/长裤/护臂/战靴/饰品的固定系数 | 全部非容器装备 |
| 改变攻击/防御机制 | **无**。没有格挡、闪避加成、反击、击中回能、破防阈值等任何装备级机制 | 0 |
| 改变技能行为 | 仅旧武器「品质专属」（紫起剑气/穿刺余波/侧球/箭雨加箭），且**绑在品质上而不是装备上** | 4 把旧武器 |
| 资源/探索便利 | `bag_gather` 采集 +1；`rig_heavy` 防御 +3 但移速 −5%；`rig_light` 移速 +10% | 3 个容器 |
| 外观/收藏 | 遗迹 5 件永久藏品（含 2 件紫装武器）、洞窟 1 件首杀藏品 | 6 |

**[推]** 装备空间里**唯一存在真实取舍的位置是容器**（格数 vs 移速 vs 采集 vs 攻击）。武器与防具的全部维度都是「更高品质 = 全面更好」。

## 3. 缺口清单

### G1 品质是严格支配关系，且无任何代价

- **[源]** 白→红：武器攻击 8 → 132（**16.5 倍**），防御 3.2 → 52.8，词缀条数 0 → 2，紫起解锁专属效果（`AdventureItems.cs:30-35`、`QualityData/*.asset`、`WeaponTraits.cs:10`）。
- **[源]** 尺寸不随品质变化（见上表），因此**没有「大件占格」这一传统制衡**。
- **[推]** 结论：在现有系统里「用低品质」永远是纯亏损，玩家没有理由保留或使用紫以下装备（除非还没打出来）。**这不构成构筑选择，只构成获取进度。**
- **[疑]** 若未来引入「高品质更大/更重」，会改变背包压力曲线——本批不实施。

### G2 新增武器完全没有品质专属效果

- **[源]** `WeaponTraits.Exclusive()` 对 `NewWeaponRegistry.Is(type)` 直接返回「独立武器机制 · 通用词缀按实际命中结算」，跳过全部品质分支（`WeaponTraits.cs:10`）。
- **[源]** 三把新武器的马达里也没有任何 `Gear.Main.quality` 读取（`NewWeaponCombat.cs`、`GreatswordCombat.cs`、`ScytheCombat.cs` 全文无 quality 分支）。
- **[推]** 后果：新武器的紫/金/红**只等于更高的 Attack 数字**，而旧武器的紫/金/红会改变攻击形态（多剑气、多箭、侧球）。这让「新武器」在纵向成长上反而比旧武器**更薄**。

### G3 「回响」词缀有一半是死词缀

| 作用对象 | 是否生效 | 依据 |
|---|---|---|
| 旧武器普攻 | **否** | 普攻 `Melee(a, a.range, ...)` 不读 `a.area`（`AdventureCombat.cs:181`） |
| 旧武器 8 个扩展技能 | **否** | `ExpandedMelee(..., c.def.reach, ...)` 直接传定义值，不乘 area（`WeaponSkillExpansion.cs:52,71`） |
| 旧武器槽 0 技能 | 是 | `Melee(a, 4*area, ...)`（`AdventureCombat.cs:186-189`） |
| 双刃 | 仅技能段（`phase>=10`） | `NewWeaponCombat.cs:32` |
| 巨剑 | 仅技能扇形 | `GreatswordCombat.cs:10`（`phase>=10`） |
| 镰刀 | 仅牵引距离与技能扇形 | `NewWeaponCombat.cs:10`；`ScytheCombat.cs:10`（`phase>=10`） |

- **[推]** 六条词缀里唯一一条「机制型」词缀（改范围）在**大部分实际输出路径上不生效**。玩家铭刻它时看到的描述是「技能范围 / 箭雨散射提高 25%」，但真正吃到它的只有 5 个技能。

### G4 「聚能」的代价只在一半路径上收取

- **[源]** 伤害 +25% 对所有「skill=true」的命中生效（`WeaponHit.cs:8`）。
- **[源]** 冷却 +1s **只在两处**被加上：旧武器槽 0（`AdventureCombat.cs:151`）与新武器（`NewWeaponCombat.cs:11`）。
- **[源]** 8 个扩展技能的冷却走 `PrepareExpanded(def.cooldown)`，**不加 1 秒**（`WeaponSkillExpansion.cs:39,66`）。
- **[推]** 结论：把「聚能」铭刻到一把用扩展技能输出的武器上，等于**白拿 25% 伤害**。这是当前词缀系统里唯一一处「无代价收益」。

### G5 新武器没有制造入口，装备追求线在中段断裂

- **[源]** `RecipeData/` 共 **29** 个配方：`gear_{type}_{2,3,4}` 覆盖 `type 0-8`（9 类 × 3 品质 = 27 个）+ `container_rig_heavy` / `container_bag_relic`（2 个）。**没有任何 type 11/12/13 的配方**，也没有白/绿配方（白绿本来就不需要解锁）。
- **[源]** `CraftingTargets.Valid()` 要求 `(int)t.type < 9`，因此**新武器连「设为制造目标」都不允许**（`CraftingTargets.cs:20`）。
- **[源]** 三把新武器的获取途径只有三条：森林小怪 3% / 精英 8%（`NewWeaponDropRules.cs:4-5`）、遗迹两件永久藏品（紫镰刀、紫巨剑）、洞窟守望者每杀 1 件（白 50/绿 40/紫 10，`CrystalCavernBossRewards.cs:40`）。
- **[推]** 后果：**「我要做一把红镰刀」这条路在当前版本不存在。** 玩家的终极装备目标只能落在旧 4 类武器或防具上，而新武器永远是「打到什么用什么」。这直接削弱了 WP02-06 的 B 方案（装备追求优先）。

### G6 盘内叠加：多件武器同时上板会叠加攻击

- **[源]** `Active => Unique.Where(i => !i.overflow && !i.worn && (i.board || i == Main))`，`Attack => Active.Sum(i => i.Attack)`（`AdventureLoadout.cs:19-22`）。
- **[源]** `CanPlace` 只禁止「容器上板」与「正在使用的武器上板」，**不禁止其它武器上板**（`AdventureLoadout.cs:97-99`）。
- **[推]** 因此把 3-4 把不用的高攻武器摆进胸挂板面，会直接把它们的 Attack 加进总攻击。胸挂 8×6=48 格最多可放约 4 把镰刀（3×4=12 格）。这是当前装备系统里**最大的非预期强度来源**，也是「主武器」这个概念在数值上被绕开的路径。
- **[疑]** 是否已有玩家利用未知；P1/P1C 的 13+3 条 Run 都没有做这件事（驱动只用起始装备）。

### G7 分解经济是单向亏损

- **[源]** 分解返还 `(int)quality + 1` 块铁矿：白 1 / 绿 2 / 紫 3 / 金 4 / 红 5（`AdventureLoadout.cs:211`）。
- **[源]** 红装制造成本：木 10 · 石 5 · **矿 10** · 晶 4 · 核心 2（`CraftingCosts.cs:12`），另加解锁累计矿 38 · 晶 26 · 核心 4。
- **[推]** 分解一件红装拿回 5 矿，连制造成本的矿都不够一半，且晶石与核心**永不返还**。分解只对「白/绿垃圾」有意义。

### G8 防具四件套都是纯防御，没有一件改变行为

- **[源]** `armor 0.4 / trousers 0.3 / arms 0.2 + 0.35 atk / boots 0.2 / accessory 0.2 + 0.5 atk`（`ItemData/*.asset`）。
- **[推]** 五个防具位之间唯一的差别是「系数高低」与「是否顺带加攻」。没有任何一件提供移速、采集、抗性、技能相关效果。**玩家的防具选择退化为「哪个品质高穿哪个」。**
- **[推] 对比**：容器反而有 3 种真实取舍（见下表），说明这套系统**已经证明自己有能力做取舍**，只是没有用在防具上。

| 容器 | 格数 | 攻 | 防 | 移速 | 采集 | 成本 |
|---|---|---|---|---|---|---|
| rig_light | 6×5=30 | 0 | 0 | **+10%** | 0 | 木6 皮3 矿2 |
| rig_standard | 8×6=48 | 0 | 0 | 0 | 0 | 木4 皮2 矿2 |
| rig_heavy | 9×6=54 | 0 | **+3** | **−5%** | 0 | 木10 皮5 矿8 + 解锁矿6 晶3 |
| bag_standard | 12×8=96 | 0 | 0 | 0 | 0 | 木6 皮2 矿2 |
| bag_gather | 10×8=80 | 0 | 0 | 0 | **+1** | 木8 皮4 矿4 |
| bag_relic | 8×6=48 | **+6** | 0 | 0 | 0 | 木10 皮5 矿8 + 解锁矿6 晶3 |

## 4. 词缀是否「无效 / 重复 / 无法影响现有武器」

| 词缀 | 无效？ | 重复？ | 能否影响三把新武器 | 说明 |
|---|---|---|---|---|
| 锐利 +15% | 否 | 否 | 能 | 唯一在所有路径都生效的伤害词缀 |
| 疾风 −18% 间隔 | 否 | 否 | 能（`BasicTempo`） | 只影响普攻节奏 |
| 回响 +25% 范围 | **半失效**（G3） | 否 | 仅技能段 | 描述与实际不符 |
| 汲取 6% 吸血 | 否 | 否 | 能 | 唯一生存向词缀 |
| 猎首 +30%（<35%） | 否 | 否 | 能 | 对 320-360 HP 的首领只在最后 112-126 HP 生效 |
| 聚能 +25% / +1s | 否 | 否 | 能 | 代价只在一半路径收取（G4） |

**[推] 词缀池的结构性问题不是「无效」，而是「全部都是乘算数值」**：6 条里有 5 条是纯伤害/生存系数，唯一一条改机制的（回响）半失效。也就是说，**铭刻无法改变打法**，只能改变同一套打法的数字。

## 5. 现有系统是否足以形成「有意义的选择」

直接回答 §5 的问题：**不足，但差距很小，且不需要新增系统。**

| 判断项 | 结论 | 依据 |
|---|---|---|
| 品质之间有无选择 | **无**（严格支配，G1） | 尺寸不随品质变 |
| 武器类型之间有无选择 | **有**（距离/形状/循环三轴，见 `WEAPON_ROLE_MATRIX.csv`） | 七把武器的判定体与周期差异显著 |
| 技能之间有无选择 | **弱**（槽 0 支配扩展技能，见 `SKILL_BUILD_MATRIX.csv`） | 倍率与冷却双重劣势 |
| 词缀之间有无选择 | **弱**（5/6 是纯数值，G3/G4） | 铭刻只能改数字 |
| 容器之间有无选择 | **有**（G8 表格） | 格数/移速/攻防真实互换 |
| 制造能否形成目标 | **部分**（旧武器/防具可以，新武器不行，G5） | 无 11/12/13 配方 |

**[推]** 结论：**不需要新增强化/重铸/升星**。缺的是三件「接线」工作：
1. 让新武器进入制造与目标系统（G5）——纯数据 + 一处 `Valid` 判断；
2. 让「回响」真正作用于它描述的东西（G3）——一处乘算位置；
3. 让「聚能」的代价在所有路径一致收取（G4）——一处冷却计算。

这三件都在**现有数据结构内**可完成，不动 v9/v10、不动经济、不动掉落。

**[疑]** 上述三条都会改变现有数值平衡，属于「改动经济/伤害」范畴，**必须单独授权**，本批不实施。
