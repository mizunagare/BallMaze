## 1. 归一化与适用范围

所有伤害以 **P = hero.AttackPower** 归一化。`ThirdPersonHero.cs:22`：

```
P = attackDamage(25) + Equipment.AttackBonus + Progression.AttackBonus
```

`Equipment.AttackBonus → AdventureLoadout.Attack = Active.Sum(i => i.Attack) + 胸挂/背包 attackBonus`
（`HeroEquipment.cs:15`、`AdventureLoadout.cs:22`）。因为本文所有指标都是 **P 的比值**，
装备品质与等级只做整体缩放，**不改变 η / B 的排序**。

适用对象：7 套普攻、4 个旧武器槽 0 内置技能、14 项扩展技能 = 25 行（`SKILL_VALUE_MODEL.csv`）。
**不适用**：品质专属追加弹体、词缀乘算、敌人护甲/减伤、暴击、伤害溢出、控制收益 —— 这些
单独列在 §6，不折算成倍率。

## 2. 符号与公式（R1 保留，不改）

| 符号 | 含义 | 单位 | 来源 |
|---|---|---|---|
| `m_p` | 第 p 次 Release 的伤害系数 | ×P | `WeaponSkillDefinition.power` / 各 Motor 的 factor |
| `D` | 一次完整施放的伤害总额 `Σ m_p` | ×P | 源码参数求和 |
| `W` | **技能占用且不能普攻的窗口** | s | 见 §2.1 |
| `C` | **从施放开始计时**的冷却 | s | `PrepareExpanded` / `UseSkill` / `SetNewCooldown` |
| `R` | 该武器纯普攻的持续输出率 | ×P/s | `Σ m_basic / cycle` |
| `N` | 场景中可命中的不同目标数 | 个 | [疑] 理论假设，见 §4 |
| `cap` | 该形状单次 Release 的覆盖上限 | 个 | [疑] 理论假设，见 §4 |
| `H` | 命中可靠性（弹体遮挡 / 瞄准 / 蓄力被打断） | 0–1 | [疑] 理论假设，见 §4 |

### 2.1 窗口 W 的源码时序（不手填，由脚本按参数算出）

| 类型 | 公式 | 依据 |
|---|---|---|
| 旧武器槽 0 | `W = 0.50`（`ActionDuration(hero.AttackInterval)`；技能不吃 `SpearCadence`） | `AdventureCombat.cs:62,74,79` |
| 旧武器扩展（非蓄力） | `W = startup + (pulses−1)×gap + 0.22` | `WeaponSkillExpansion.cs:48-49` |
| 旧武器扩展（蓄力） | `W = charge + startup + 0.22` | `WeaponSkillExpansion.cs:46` |
| 新武器技能 | `W = startup + Σ段间隔 + 收招` | `NewWeaponCombat.cs:43-44`、`GreatswordCombat.cs:5-6`、`ScytheCombat.cs:5-6` |

### 2.2 四个输出指标

```
D(N,H) = (Σ m_p) × min(N, cap_skill) × H_skill
R(N)   = (Σ m_basic / cycle) × min(N, cap_basic) × H_basic
G      = D − R × W                         净收益
B      = D / (R × W)                       窗口内爆发系数
E      = (D + R × max(0, C − W)) / C       一个完整冷却周期的平均输出率
η      = E / R                             相对纯普攻的持续效率
```

**[推] 核心恒等式**（代入即消元）：

```
η = 1 + (B − 1) × W / C
```

这条恒等式决定了整个 03A 的调整策略：

1. **B < 1 时，任何冷却调整都无法修复** —— 降低 C 只会把 η 压得更低。必须先增大 `D` 或减小 `W`。
2. **B > 1 时**，降低 C 会放大收益，但幅度受 `W/C` 限制：长窗口技能即使 B 很高，η 也只能贴近 1。
3. `W/C` 是结构常数：槽 0 `0.5/7 ≈ 0.071`，扩展技能 `0.05–0.19`。**「把扩展技能倍率对齐槽 0」是错误目标**。

### 2.3 模型边界（R1 明确列出，不是完整实战 DPS 模拟）

| 假设 | 内容 |
|---|---|
| `W` | 技能占用且不能普攻的窗口 |
| `C` | 从施放开始计时 |
| `C ≥ W` | 冷却不短于窗口（脚本逐行 `assert`） |
| 冷却剩余 | 按**纯普攻输出**填满，是保守下界 |
| 不考虑 | **两个技能交替、敌人移动、遮挡、打断、目标死亡溢出、控制收益** |
| 不混算 | 控制收益、AOE 覆盖、贯穿、命中可靠性**不折算成单一等效倍率** |

## 3. 三条目标带与统计口径（R1 分离）

| 带 | 适用 | 门槛 | 数量 |
|---|---|---|---|
| **T1** | 无独占机制的纯输出技能 | `B ≥ 1.10` 且 `η ≥ 1.01` | 1 |
| **T2** | 有独占机制的输出技能 | `B ≥ 1.00` 且 `η ≥ 1.00`，并在至少一个已定义场景优于槽 0 | 11 |
| **T3** | 条件触发 / 纯控制 | **η 与 B 不适用**，另设专属指标 | 2 |

### 3.1 R1 硬规则

- **14 项总数保留**；**T1/T2 = 12 项**是唯一使用 B/η 做目标判定的范围；
- **T3 = 2 项**：`twin.counter`（条件反击 1）、`sc.pull`（纯控制 1）。
  B/η 数值可保留在 `SKILL_VALUE_MODEL.csv` 附录列（`metric_status = APPENDIX_ONLY (T3)`），
  但 `target_check = N/A (T3)`，**不得作为 T3 目标判定，也不计入通过率**；
- **`MODEL_PASS` / `MODEL_FAIL`** 只表示**离线模型**是否落入目标带，**不是真实战斗通过**；
- 原始数值冻结：`sc.pull` 保持 `startup=0.40`、`cooldown=11`、`D=0`；
  `twin.counter` 保持 `startup=0.28`、`C=8`、常态 `0.65×` / 强化 `1.80×`。

### 3.2 `8/14` 与 `6/12` 的正确解释（R1 修正）

| 数字 | 口径 | 含义 |
|---|---|---|
| **8/14 B<1** | **全 14 项（含 2 个 T3）** | 包含 `twin.counter`（0 伤害条件反击）与 `sc.pull`（0 伤害纯控制）。**这 8 个里有 2 个根本不是输出技能，因此「8 个输出技能弱于普攻」是错误表述。** |
| **6/12 B<1** | **T1/T2 输出技能** | 8 − 2 = 6。这才是「输出技能严格劣于同窗口一直普攻」的现状计数，由脚本 `assert b_lt1_t12 == 6` 保证。 |

`MODEL_SUMMARY.csv` 与 `Evidence/Tools/model-run.json` 的 `statistics` 字段逐项记录：
`total=14, t1=1, t2=11, t3=2, t3_conditional=1, t3_control=1,
b_lt1_all=8, b_lt1_t3=2, b_lt1_t12=6, model_pass=12, model_fail=0, focus_pass=8`。

## 4. 假设与敏感度（必须标注 [疑]）

| 假设 | 取值 | 性质 |
|---|---|---|
| `cap_basic` | 长剑 3 / 长枪 2 / 法杖 2 / 弓 1 / 双刃 2 / 巨剑 4 / 镰刀 4 | **[疑] 理论假设，非 Player 实测** |
| `cap_skill` | 逐技能 1–5，见 `SKILL_VALUE_MODEL.csv` 的 `cap` 列 | **[疑] 理论假设，非 Player 实测** |
| `H` 主模型 | 全部 = 1.0（全命中理论上界） | 避免把猜测写进主结论 |
| `H` 敏感度 | 近战恒 1.0；弹体/蓄力/留场/控制类取 `{1.0, 0.8, 0.6}` | `SENSITIVITY.csv`（162 行） |
| `N` 敏感度 | `{1, 3, 5}` | 同上 |
| 冷却期内行为 | 施放结束后一直普攻 | 保守下界；实际可交替两个技能，收益更高 |

**[推] 反直觉结果**：当技能与普攻的 `cap` 相同且 `H` 相同时，`η` 与 `N` **无关**。
也就是说 **AOE 只有在「技能覆盖目标数 > 普攻覆盖目标数」时才产生净收益**。
例如 `sword.circle`（360°/3.1m，`cap=5`）对长剑普攻（75.5°/1.8m，`cap=3`）：
在 N=5 的包围场景才真正优于普攻；N=1 时因 `W=1.50s` 反而更差。

## 5. 模型算出的三个结构性发现

### 5.1 七把武器的普攻 DPS 是两个梯队

| 梯队 | 武器 | R (×P/s) |
|---|---|---|
| 高 | 长剑 / 法杖 / 弓 | 2.000 |
| 中 | 长枪 1.923、双刃 1.878 | — |
| **低** | **巨剑 1.000、镰刀 1.000** | — |

**[源]** 巨剑 `1.05× / 1.05s`、镰刀 `0.80× / 0.80s`。
**[推]** 巨剑/镰刀持续输出只有长剑的一半，靠 65°/85° 扇形与 2.6/3.0m 距离换多目标覆盖。
任何「把倍率调到和长剑一致」都会破坏这个交换。

### 5.2 T1/T2 中 6/12 的 B<1

| 技能 | 现状 B | 现状 η | 主因 |
|---|---|---|---|
| `sword.circle` | 0.550 | 0.939 | `W=1.50s`（gap 0.48×2）吃掉收益 |
| `bow.pierce` | 0.701 | 0.959 | `W=1.52s`（蓄力 1.0 + 0.3 + 0.22） |
| `staff.echo` | 0.711 | 0.963 | `W=1.16s` 三段分时 |
| `gs.wave` | 0.731 | 0.965 | `W=1.30s` 且单发 0.95× |
| `spear.charge` | 0.881 | 0.983 | `W=1.31s`（蓄力 0.85 无保护） |
| `bow.burst` | 0.907 | 0.991 | 0.55× 三段总量偏低 |

**另外 2 个 B<1 是 T3**（`twin.counter` 0.666、`sc.pull` 0.000），按 §3.1 **不纳入本表统计**。
其余 6 项 T1/T2 的 B 在 `1.05–1.65`，η 在 `1.004–1.044`；4 个旧槽 0 的 η 是
`1.071 / 1.107 / 1.086 / 1.357` —— T1/T2 扩展技能没有一项达到对应槽 0。

### 5.3 品质缩放不对称，是比倍率更根本的断层

| 槽 0 | 白 D | 红 D | 倍率增长 |
|---|---|---|---|
| `sword.whirl` | 2.00 | 4.25 | ×2.13 |
| `spear.thrust` | 2.40 | 4.20 | ×1.75 |
| `staff.meteor` | 2.20 | 3.80 | ×1.73 |
| `bow.rain` | 6.00 | 10.80 | ×1.80 |

**[源]** `AdventureCombat.cs:186-189`。**14 项扩展技能全部不吃品质**。
**[推]** 玩家装备越好，槽 0 越强、扩展技能原地不动 —— 差距随进度单调扩大。
**但 R1 明确：品质专属 9 条全部 `DESIGN_ONLY`，不进默认包**；03A 只让 T1/T2 的 12 项
在独占场景成立，不追平倍率，也不给 14 项都加品质加成。

## 6. 不折算成倍率的六个维度

| 维度 | 本文的表达 | 为什么不能折算 |
|---|---|---|
| AOE | `cap_skill` vs `cap_basic`、`half_angle_deg`、`reach_m` | 收益只发生在「技能覆盖 > 普攻覆盖」的场景 |
| 贯穿 | `bow.pierce` 最多 3 个不同目标、`gs.wave` 8m 行程 | 依赖敌人排队，不是伤害系数 |
| 控制 | `gs.cleave` 破防 0.75s、`sc.pull` 牵引 1s；Boss 免疫 | 价值 = 取消一次敌人攻击，与血量无关 |
| 前摇 / 恢复 | `W` 拆分到 `startup / gap / charge / recovery` | 决定「会不会被打断」，不决定伤害 |
| 实际命中率 | `H` 敏感度列；弹体要过 `Sight` | 理论假设，必须 Player 实测 |
| 场景切换成本 | `Select(slot)` 每局重置（D-03 未授权） | 构筑成本，不是战斗数值 |


自检不变量（脚本内 `assert`，任一不成立即中止生成）：

1. `η = 1 + (B−1)×W/C`（内部全精度最大误差 1.11e−16；CSV 保留 4 位小数，误差 < 5e−5）；
2. `C ≥ W` 对所有 25 行成立；
3. `total=14`、`T1+T2=12`、`T3=2`（条件 1 / 控制 1）；
4. `B<1_all=8`、`B<1_T3=2`、`B<1_T1T2=6`；
5. 提案后 T1/T2 **12/12 `MODEL_PASS`**，T3 两项 `N/A (T3)`；
6. E-A 补 `+1s` 后 8 个旧扩展技能 **8/8 `MODEL_PASS`**；
7. `T3_SKILLS` 的 id 不得出现在 `PROPOSALS` 的任何数值键里（R1 冻结）；
8. 所有提案只改 L1 常量，`D/W/C` 之外的判定参数一行未动；
9. 品质专属 9 条 `in_default_package = NO（DESIGN_ONLY / 不进默认包）`。
