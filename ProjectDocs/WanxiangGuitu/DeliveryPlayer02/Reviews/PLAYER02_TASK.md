## 4. P02-01：审计并实现隔离运行时驱动

先检查 `GameEntry`、`TitleMenu`、`PlayerInput`、`InputSettingsPanel`、`PlayerInventory`、`InteractionResolver`、`AdventureFlow`、`CombatSession`、`CombatSaveSystem`、`CampRuntime` 和现有 Gather 驱动。

建立 `PlayerAcceptanceDriver`，要求：
- 作为运行时组件启动，不依赖 `UnityEditor`、`-executeMethod` 或 Editor assembly。
- 只负责安排输入、等待真实条件、采集只读证据和生成测试回执。
- 优先用虚拟 Keyboard/Mouse 经过 `PlayerInput`、EventSystem 和正式消费者。
- 路线/战斗自动化必须通过运行时可用的导航、交互、命中与结算入口。
- 若某步骤只能由 Editor 直接调用，先尝试真实 runtime UI/动作入口；仍无法完成时记录精确阻断，不得改成直接设置最终状态。

## 5. P02-02：标题、继续与设置

在隔离测试 Player 验证：
1. Missing：缺档启动标题，不创建 Run。
2. Ready：合法档启动标题，实际继续/读取并进入正确 Run。
3. New Game：确认期间存档指纹变化，必须拒绝并要求重新检查。
4. Settings：标题打开设置，改键后取消，有效绑定不变。
5. Apply：修改键位、应用、关闭设置、重启 Player，绑定保持。
6. Corrupt/Incompatible/Pending/Committed：状态准确，不覆盖原始输入。
7. 优先经 runtime UI 输入路径点击按钮；直接调用回调只能标记为“受控 UI 回调”，不能声称 UI 输入链通过。

保存启动参数、合成存档哈希、场景、Profile/Run 身份、输入事件、UI 状态、回执、进程退出状态。

## 6. P02-03：键位实际消费与提示一致性

- 从游戏设置 UI 修改至少三个不冲突动作：移动、游戏动作（交互/闪避/技能之一）、管理/页面动作。
- 经过正式 `PlayerInput` 采样和真实消费者验证动作生效。
- 检查 HUD、交互提示、帮助和教程的显示键位与有效绑定一致。
- 覆盖按下/按住/释放、设置打开、捕获、Esc取消、冲突拒绝、焦点/设备恢复、坏设置、保存失败及新进程恢复。
- 明确区分虚拟设备验证与原生 U16；虚拟测试不能关闭原生验收缺口。

## 7. P02-04：正式 Player 完整搜打撤纵切

执行真实运行链：

标题 → 继续/进入合成档 → 森林移动与探索 → 真实拾取 → 收费渡口修复（路线要求时）→ 实际出口交互 → 撤离 → 结算提交 → 回营 → 仓库核对 → 取材 → 制造 → 再次出征 → 新进程恢复后继 Run。

每个阶段记录：
- Profile、Run、区域、种子、布局修订和装备身份。
- 前后库存、来源账、地面掉落、扣费、出口回执、结算阶段和随机流状态。
- 实际进程、命令、退出码、超时、原始日志与状态快照。
- 失败、中断、未知终态和重复提交结果。

状态变化必须由正式游戏运行时代码产生。不能直接改 JSON、跳过碰撞/交互/拾取、调用 Editor 驱动或伪造结算回执。新进程恢复必须真正启动新进程。若当前 runtime 架构确实不能完成某步骤，保留复现并报告阻断，不能把该步骤标为 PASS。

## 10. 原生、人工与性能边界

- 原生键鼠 U16 和独立人工试玩只有在有明确授权、不会抢占用户桌面的独立交互环境中执行；否则标记 `NOT_RUN`。
- 虚拟输入、自动化 AI、后台 `WM_CLOSE` 和截图均不能替代物理操作或人工可理解性。
- 完整性能基准需固定场景、分辨率、画质、目标硬件和采样方法，记录 CPU/GPU 帧时间、内存/显存、GC 与加载时间。若未采样，标记 `NOT_RUN`。
- D3D12 `UNKNOWN`、Editor 青色帧、Editor Search、JobTempAlloc 根因继续 `UNRESOLVED`，本批不顺带做无依据的生命周期试探。

## 11. 通过标准

PLAYER-02 只有在以下条件全部满足时，才可声称“正式 Player 自动化冒险纵切通过”：
1. 正式 Player runtime 驱动不依赖 `UnityEditor`。
2. 标题/继续/设置/改键消费通过正式 Player runtime 输入/UI 路径。
3. 真实搜打撤链从进入游戏到撤离、结算、入仓、制造、再次出征完整运行。

5. 测试驱动被证明不进入正式发行构建。
6. 所有失败和未执行项如实保留，受影响回归完成。

即使上述自动化通过，原生 U16、独立人工试玩与性能基准仍须分别验收，不能自动关闭。
