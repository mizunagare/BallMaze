# B09 存档模型与失败处理

## 现状

当前仍为一个 v9 自动保存封装：主档 save.json、备份 save.json.bak、ground-loot 分页、迁移与恢复档案。ProfileState、RunState、SettlementRecord 共处一个完整封装，沿用修订号、校验和与原子写入。没有新增槽位索引，没有改变存档版本。v1～v9 继续由原 ReadChecked/LoadProgress 迁移与恢复。

默认 Company Name 不变，旧位置为 DefaultCompany/BallMaze/ForestRuins，新位置为 DefaultCompany/万象归途/ForestRuins。测试严格使用启动参数指定的隔离根：Legacy/ForestRuins 与 WanxiangGuitu/ForestRuins。本轮不读取真实目录。

## 状态边界

- 营地：Profile 与营地检查点，不创建 Run。
- 在途/引导：恢复同一 Run、区域、seed、布局、随机流、来源账及教程。
- Pending：继续原待确认结算，不提前提交。
- Committed 未 acknowledged：恢复已保存结果，仍由原回营确认入口处理。
- 损坏且无有效备份：不可继续，保留原文件。
- 不支持的版本：不可继续，不回退成空档。
- 有效备份：可恢复完整备份；目录与页由原保存器校验。
- 未发布 tmp：明确标出不确定写入，只允许读取最后有效修订。
- 新旧目录都有集合：必须明确选择；不合并，复用 A1 选择回执。

## 新游戏事务（不是 Restart 的别名）

明确确认全部重置后，对当前和旧目录重新计算指纹；进入场景前复核。以独占 entry.lock 防并发，候选保存到同级 GUID staging；使用原保存器写完整候选，校验 v9、独立 Profile ID、无 Run/结算。先写并落盘事务 journal，原集合整体移动到 GUID archive，再发布 staging，核对实际 Profile ID 与完整集合指纹，最后记录 committed。

发布前失败不替换旧集合；原集合已经归档但未发布时，只有指纹匹配且目标不存在才原样恢复。已经发布但回调失败时，先核对实际新集合；不盲目回滚或再次创建。状态不明则保留候选、归档与 journal，阻止自动覆盖。归档包含备份和所有分页，不只复制 save.json。旧位置保持；明确新游戏时为新集合建立原迁移器选择回执。设置在集合外，保留。

新档不混入旧仓库/配方/徽章/教程；旧档归档可离线恢复，但本轮没有伪造“档案槽”浏览或一键恢复归档 UI。失败时不会将候选内存进度自动写回旧位置。

## 合成验证

测试新游戏 staging/归档/发布故障、发布后回调故障、进程边界恢复、读取失效快照、状态分类、集合指纹与旧版本回归。全部使用工程外唯一根。Editor-only 的 EntryInterruption 是受控事务边界试件，非崩溃/强杀；正式程序集剔除。日志和断言与真实 Player 背景关闭/恢复分开记录。

入口在首次确认后锁定 Loading/request，连点不能同时请求第二次场景加载或第二次新档创建；控件停用与业务入口共同防重复。

v1～v6 的自动档列表明确标为旧版波次在途、继续时迁移；它们尚无 Profile/Run ID，不在只读阶段伪造 ID 或将其误标为营地。实际读取仍由原兼容链创建迁移保护 Run。缺失的保存时间显示“未记录保存时间”。

被启动校验拒绝后，标题、旧 ForestRuins 自动初始化与显式 InitializeStorage/InitializeFromEntry 均不访问存档，角色输入保持关闭。Editor 不因校验退出应用；Player 使用预期错误退出码2。

集合指纹以流式 SHA-256 读取，保持既有指纹格式，不以新增总字节常数拒绝大型分页/归档集合；原主档/分页校验预算不变。257MiB 零文件试件只验证管理层流式指纹，不冒称海量掉落玩法验收。

## 原有业务语义不变

| 数据 | 继续与读取 | 明确确认新游戏 |
| --- | --- | --- |
| Profile ID、仓库、配方、徽章、首次 Boss 奖励回执 | 原值恢复 | 独立新 Profile；旧集合完整归档 |
| Run/区域实例/seed/布局 revision/随机流 | 原样恢复，不重新抽取 | 无旧 Run，在营地准备后另建 Run |
| 装备 ID、容器布局、双武器与冷却 | 原保存器负责恢复 | 不从旧内存或旧永久仓库混入 |
| B1 扣费回执、来源账、地面掉落分页 | 原样恢复，不自动拾取或重新扣费 | 留在归档，不移植到新 Profile |
| Pending / Committed / acknowledged | 原唯一结算入口继续处理，不由标题发布奖励 | 不把旧终局记录并入新档 |
| hasTutorial 与教程阶段 | 原样恢复，不重播奖励 | 新教程初始状态 |
| 音量/镜头/HUD/画面设置 | 集合外独立设置 | 保留 |

当前没有独立角色槽、删除档案界面、云同步或归档浏览恢复功能。菜单的“读取存档”明确显示所示自动档，不能被解释为多槽读档。原完整归档用于安全恢复与诊断，并不自动合并任意两个 Profile 或 Run。

故障注入、受控中断与新进程恢复都是合成数据；它们验证事务边界，不等于覆盖所有磁盘硬件故障。没有用实际断电或强杀证明整机崩溃恢复。正式 Player 的保存/退出/继续另外核对退出审计及集合修订。

## 新增侧文件的版本边界

主存档仍v9；没有新增持久化槽位索引。集合外preferences.json为version1，非法/不支持设置只回退内存默认，不在读取时覆盖原文件；用户明确“应用并保存”才写。新游戏事务journal为version1，缺失时无需恢复，非法版本/记录返回受阻并保留文件，不用空档冒充成功。主/备份、分页、来源账、hasTutorial、徽章及首次奖励、B1扣费和B3随机流由原封装继续保存。

最终All5实际PASS：B09Rules四进程、B09Cases真实Pending/Committed加载、旧版迁移链和Entry三进程；另最终Player两进程核对同一后继Run。对应JSON/审计见Evidence/INDEX，不用Editor-only钩子冒充生产崩溃。
