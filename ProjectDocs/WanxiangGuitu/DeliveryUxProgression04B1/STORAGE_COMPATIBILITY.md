# UX-04-B1 存储兼容性审查（B1-01）

> 本文件对应实施规范的 **B1-01 存储路径审查（8 项硬门禁）**。所有结论基于产品源码静态审查与真实存档读档运行（见 `ACCEPTANCE.md` F9/F10）。

## 一、审查目标

确认「高品质装备不可分解」落地前，**金 / 红品质装备在存储与读取层面不存在被卡死、无法入库、无法读取的脏状态**，否则须 STOP 上报。

## 二、8 项硬门禁逐条结论

| # | 审查项 | 结论 | 依据 |
|---|---|---|---|
| 1 | 金/红能否进入普通容器（背包 / 装备盘 / 胸挂） | ✅ 能 | `InBag = !board && !overflow && !worn`，**品质不参与**判定；`Fit`/`Cells` 仅按类型/尺寸 |
| 2 | 容量限制是否歧视品质 | ✅ 否 | `DepositEquipment` 只校验 `InBag` 与 `CampRuntime.Capacity` |
| 3 | Overflow（迁移暂存）处理 | ✅ 完整保留 | 提供「取回背包」路径，暂存态不改变品质与可读性 |
| 4 | 既有金/红存档读取兼容 | ✅ 兼容 | `ValidateCurrentItem` 用 `quality < 5` 校验，金(3)/红(4) 均通过 |
| 5 | 穿戴拒绝（worn）装备能否入库 | ✅ 受业务约束（非脏态） | worn 装备须经脱下解锁，属正常流程，非 B1 范畴 |
| 6 | 存取是否改变属性 | ✅ 不改变 | `DepositEquipment` / `WithdrawEquipment` 为对称归属移动，零属性改写 |
| 7 | 是否存在不可入库状态 | ✅ 仅临时态且均有产品解锁路径 | `worn/board/overflow/Carried` 均为业务逻辑态，存在对应解锁（脱下/取回/移出） |
| 8 | 是否存在不可分解 / 不可处理状态 | ✅ 均为显式可识别态 | `ProtectedEntry`（入场保护）与 `SalvageAllowed`（B1 锁定）均为代码中可读布尔，非隐式脏数据 |

### 关键代码锚点

- **入库（`CampRuntime.DepositEquipment`）**：仅检查 `InBag && !Carried` 与仓库容量，**不检查品质** → 金/红可正常入库（实测 F6：金 10→9 离包，仓库 0→1）。
- **取回（`CampRuntime.WithdrawEquipment`）**：对称路径，不检查品质（实测 F7：仓库 1→0，包 9→10）。
- **读取（`CombatSaveSystem` / `CombatSaveData`）**：v9 Schema 下 `quality` 字段为 0–4 整数，金/红读取无异常（实测 F9/F10，`version=9 revision=4`）。
- **容器适配（`Fit` / `Cells`）**：依 `item.Size`（类型/尺寸）计算占位，与品质无关 → 金/红装备在背包 / 装备盘 / 胸挂中占位与原规则一致。

## 三、是否存在「不可入库」装备？

**结论：否。**

- 所有「不可入库 / 不可处理」情形均来自明确的业务态（`worn` / `board` / `overflow` / `Carried` / `ProtectedEntry`），每态均有产品内对应解锁动作。
- B1 新增的 `SalvageAllowed` 仅影响**分解**，不影响**入库 / 取回 / 读取 / 占位**。
- 因此 B1-01 **门禁释放**，无需 STOP，可继续 B1-02 / B1-03。

## 四、临时状态全景（含 B1 新增）

| 状态 | 含义 | 可入库 | 可分解 | 来源 |
|---|---|---|---|---|
| `InBag` | 背包内 | — | 视品质 | 基础态 |
| `worn` | 穿戴中 | ❌（须脱下） | ❌ | 装备穿戴 |
| `board` | 胸挂内（已生效） | ❌（须移出） | ❌ | 胸挂 |
| `overflow` | 迁移暂存 | ❌（须取回） | ❌ | 容器溢出 |
| `Carried` | 携带（出征） | ❌（须卸下） | ❌ | 出征携带 |
| `ProtectedEntry` | 入场保护 | ✅ | ❌（保护） | UX-03 规则 |
| `SalvageAllowed=False`（B1） | 金/红禁分解 | ✅ | ❌（B1 锁定） | B1-02 |

> 可见：B1 锁定态**不影响入库**，与「不可分解 · 可入库」文案语义一致。
