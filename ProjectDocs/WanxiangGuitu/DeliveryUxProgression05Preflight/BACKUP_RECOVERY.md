## 版本与事务政策 [D]

| 输入 | 单窗口候选政策 |
|---|---|
| v9 | 严格读取。确有 Schema 需求且另获授权后，直接迁至唯一目标版本。 |
| 获批目标版本 | 同版读取与检查列表幂等，无迁移写。正常保存单独递增 revision。 |
| 未支持版本 | 区分不兼容与损坏，阻断同根写入及静默回退。旧 v10/v11 方案不产生兼容链。 |
| v1–8 | 保留既有兼容路径；本方案的源基线为有效 v9。 |

[D] 先验证完整旧档备份，再原子发布一次目标世代。用户取消、浏览档案或同版加载均不触发迁移。验证链 v6 写入与生产 writer 隔离。

1. **冻结与选源。** 仅在明确触发并获移档授权后，将规范化根、profile、事务 token 绑定到独占写者。暂停初始化、新游戏、F5、自动/生命周期保存、仓库/结算和输入解冻。以严格读器选可验证源，多版本按矩阵，避免权限/锁故障被误判为档坏；读取原始 bytes、证据清单与语义，记录预期当前主/备状态（包括缺失）和父世代。读取 v9 使用 v9 规则，并保留现有格位与装备尺寸。
2. **先备原档。** 原主档、滚动备档、它们及已保留迁移归档所引用分页、校验信息、必要事务状态（含适用的 journal、回执与恢复指纹）、迁址凭证和关联文件及版本信息，按 relative-path/长度/SHA-256 冻结；按各自版本验证可恢复候选，损坏对象也可保留为标明不可恢复的原始证据。目录须独立，不能是根内会被活动保存覆盖的目标，完整 snapshot 可按 profileId/sourceVersion/revision/原始 envelope hash 和唯一事务 ID 命名；先写同卷独立 stage，确认已落盘且可用源版本规则离线验证，再发布只增不可覆盖归档。原主坏以备为基线时保存坏主与好备原件，绝不让坏主旋转覆盖好备。不得仅因已有同版本文件名就跳过原始 bytes 验证。相同源和目标的既有有效归档可按清单复用，以免重试无限生成副本。
3. **构造与验证。** 只对分离 DTO 转换，不发物品、不更新运行时/随机源。生成目标外壳（schema version 与 revision 分离；建议此次发布在锁下 checked parent+1，外壳/内层一致，回档分支不与另一分支直接比 revision）。明确字段存在性、类型和边界，不能把 JsonUtility 的默认或未知字段丢弃当成功；拒绝不支持的 schema/目录。准备页并核验 SHA、大小、计数、顺序、实体 ID，先耐久化再写引用它们的 staging envelope；从 staged 文件用目标 reader 全量重读、做许可差分（见 [一次性迁移窗口](MIGRATION_V10.md)）。原始 checksum/字节验真与规范语义差分独立记录。
4. **提交与确认。** 同卷以排他 CreateNew 写每笔唯一临时文件，Flush(true)，发布前再次比对主/备原始摘要、预期版本/revision/profile 及父指纹；任何差异即放弃写，重新选源。用已验证的替换/重命名原语发布单个主 envelope，保证上一世代有独立可恢复副本，禁止跨卷 copy/delete 假扮原子发布。发布后仍持锁，以实际主档重读预期事务对应的 digest、版本、revision、语义与页，后写可核对迁移回执，再解锁加载；回执不是唯一提交标志，需有已持久化的预期源/目标指纹供发布后但回执丢失时判定。发布后状态不明先冻结所有写、核对，不盲重试。不清理当前或历史引用页。

[D] 并发防护候选：同一规范化根拒绝链接/别名，强制单写者持有 OS 排他锁，并用 compare-and-swap 式父世代检查覆盖从选源到回读确认的窗口；所有写入口遵守同一锁与期望世代，不可顺序双写；只读展示可读最后确认世代或提示繁忙。锁不能靠文件 mtime 或 PID 单独判死（PID 复用）；崩溃待 OS 释放且可确认不再为活 writer，验证并隔离旧 staging，不抢锁。对于不配合锁的 v9 老构建，CAS 不消除检查和替换之间的竞争，**不允许旧端和新端共享一个可写根**；候选为升级用独立根/新路径，或可靠阻断旧二进制访问旧根后再原地迁移。云同步/网络卷、权限漂移、占用、磁盘满均是受阻，不做无锁或非原子回退。[H] Windows Unity/Mono 上文件/目录刷新、断电后的重命名持久性及第三方 writer 行为须独立故障测；现有 Flush 与 Replace 源码不足以证明断电耐久。

## 中断恢复判据 [D]

| 场景 | 恢复动作 / 校验 |
|---|---|
| 归档未完成/未通过校验，或只写了部分页、临时外壳 | 原主/备不动，保留或隔离中间证据；不从 .tmp 提升，不发奖，待修复空间/权限后从已确认世代重试。 |
| 原子发布前被杀 | 若原主仍匹配完整父世代，使用父；重复转化不重复生成归档或记账。 |
| 发布后、回执/内存确认前中断 | 回读若完全匹配预期子世代，仅补确认并加载，不再迁移/结算；若完全匹配父世代，视为未发布；两者皆不符或分页不全时冻结，展示现存主档、备档和暂存清单供核对，不用最大 revision 猜。 |
| 普通 Pending/Committed 结算跨迁移/中断 | 保留已有结算状态和计划；验证提交确实包含预期 profile、plan、run/settlement 键、奖励与实际获批的记录字段。Pending 不自动 Commit，Committed 不重复发放，ack 不是重放入口。 |
| 物理损坏/缺失，备档完整且同属允许恢复世代 | 显示版本、时间、revision、可能失去的进度；按获批策略明确选择备档，先归档候选，不自动覆盖唯一好备；主档有效优先于旧备。 |
| 未来版本/缺少定义或不同世代、权限/锁阻断、主备都坏、只剩 .tmp | 区分不兼容、受阻、坏档；不自动静默降级、不新建空档覆盖、不修改原集合。向操作员提供迁移/恢复路径；源失配时停止并刷新。 |

## 备份验收与判定记录

[D] 清单将原始封套 SHA-256、payload 校验、分页 SHA-256 分列，并记录路径、存在性、字节长度、源版本、修订号、profileId 与关联事务。记录归档、当前和暂存的角色，避免把同一文件名当成同一世代。必要事务记录落在集合旁时也纳入。对正在推进的目录事务先隔离并核对或停止，不能靠拷贝活动锁把进程所有权转移到恢复根。

[D] 加载业务前核对迁移标记和实际主封套的父/子指纹。保持独占直至留存原始故障信息和确认结论。确认子档已发时只补迁移确认。确认仍是父档且所有依赖有效时可重试。父子皆不匹配、备份缺页、清单不完整或未知挂起状态时冻结写入。完整的恢复演练使用独立克隆、原版加载和逐文件哈希核对，保留源集合与新世代供人工复审。

## 回退到旧版快照 [D]

只支持恢复完整的旧版冻结快照，不支持给当前 JSON 改 version、删除新字段、混合页或拼接旧 .bak。回退前停所有写者，封存新版主/备/页及诊断；给用户展示旧版目标版本、revision、时间、所属 profile/世代及将放弃的新增记录以及快照后的装备、库存、解锁、地图、结算等进度，确认后克隆完整集合到独立的旧版本可写根；核验清单/页、用旧版正确解析再启用。旧档副本的字节可无损恢复，但把新版进度回退到快照**不是无损**；不保证把新旧进度重新合并。保留原新版与老版快照，任何清理按获批保留周期及所有根/归档可达性进行，不自动删除唯一好档。回退与备份均须在后续隔离环境审批验证，不是对真实存档的操作说明授权。

[C] 设计示例：父 v9/r41 单次发布目标版本/r42。发布前中断继续使用 r41，发布后未确认时回读指纹匹配则只补确认，迁移重试不生成 r43。以后正常玩法推进到 r50，恢复 r41 只还原该快照。[H] 由后续获批的 [隔离 Player 验收](PLAYER_ACCEPTANCE_PLAN.md) 验证。
