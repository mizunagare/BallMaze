## 1. 修正首次／重复击杀提示

沿 C2.4 专用死亡、保存和确认入口追踪提示来源。区分两件事：本次击杀是否首次产生首奖，以及该次死亡检查点是否已经可靠写入。不能仅凭档案中存在首奖回执或仍有待领物就断定本次是首杀。

| 场景 | 玩家应看到什么 |
|---|---|
| 首次击杀，死亡检查点尚未确认 | 可以提示正在保存或可重试；不得提前显示“首奖已记入营地” |
| 首次击杀，持久化成功或完整读回确认成功 | 告知首奖可回营领取，普通战利品仍需拾取并撤离 |
| 同档案新 Run 再杀 | 仅告知本次普通战利品；无论旧首奖是待领、已领还是已拆解，都不声称本次新增首奖 |
| 写入失败或确认丢失后重试 | 不把未确认显示成成功，不把同一成功重复播报成第二次获奖 |

优先复用现有判定和事务上下文，仅修正 C2.4 提示时机与文字；不得为显示消息新增存档字段、改变首奖身份、普通掉落或保存算法。在隔离合成档上验证真正的玩家提示、回执和库存；记录触发顺序。复用现有故障入口，不重跑已经成立的全部奖励生命周期。

## 2. 修正同一 Boss 的显示名称

先追踪顶部 Boss 栏、肩后辅助目标提示各自从哪里取名，再选择最窄的非冻结展示入口。对于 C2.4 当前守望者实例，两处都显示“晶脊守望者”；同模型的原森林守卫仍显示原名。用肩后弓或杖对准活 Boss，记录实体 ID、两处文字及同帧画面；用旧森林目标作负例。仅改展示，不能用全局字符串替换，也不能用改锁定目标、权重、镜头或重命名整套复用资源来掩盖问题。若只能通过冻结文件修复，停在调用链和最小差异提案，不越权实施。
