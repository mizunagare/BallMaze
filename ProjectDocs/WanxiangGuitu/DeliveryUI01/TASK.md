## 1. B1 复审摘要

### 1.1 保留的实现

1. `AdventureFlow.Exits.cs / RepairExit` 通过原材料扣除入口更新库存及本局/带入来源账，再与修复状态、回执在同一个完整检查点发布。
2. 修复回执使用 RunId、区域实例 ID、出口 ID；领域方法检查距离、状态、材料和重复修复，非仅禁用按钮。
3. 保存失败后先读取并校验主档。若新修订和修复回执已发布，恢复已发布快照；若仍为旧修订则还原材料、账目和修复状态；结果无法确认则冻结等待恢复。不退化成简单的“false 就退款”。
4. `ForestLayout` 支持旧 revision1 与新 revision2；缺少新字段的旧出口默认免费，旧在途不插渡口、不换种子。免费普通出口的存在受到校验。
5. `WGB1Check` 有重复调用、混合来源消费、死亡不返已花材料、保存前后错误、引导取消、免费出口重叠选择、旧布局及跨进程恢复用例。
6. `latest-method-status.json` 记录 22 个方法最后结果通过，并保留结果来源。它不是单轮 22 方法从未失败的证明。
7. `Invoke-ReleaseResume.ps1` 使用窗口关闭请求，检查退出码、quit 回执及同 Run/修复/来源账快照，超时强杀判失败；报告记录两次正常退出。源码与提交记录的审查不等于审核者自己执行过。
8. 保留报告里的人工试玩、真实断电、完整 B06 与发布验证 NOT_RUN；一键包装器未整轮执行也继续如实标注，不能用分步成功推导包装器已执行。

### 1.2 必须修复：B1-UI-R01（P2）显示 E 拾取，实际却可能付费修复

位置：
- `Assets/CombatPrototype/PlayerInventory.cs / RefreshInteraction`
- `Assets/CombatPrototype/PlayerInventory.cs / InteractNearest`
- `Assets/CombatPrototype/PlayerInventory.cs / OnGUI`
- `Assets/CombatPrototype/AdventureFlow.Exits.cs / CurrentExit、InteractExit`

目前 `RefreshInteraction` 和 `OnGUI` 只按掉落/事件产生 E 的文字；`InteractNearest` 另外比较出口距离，出口更近时调用 `Flow.InteractExit()`。

触发条件：角色处于未修渡口范围内、随身材料足够；附近有可拾取掉落，掉落距离比渡口更远。画面可以显示“E 拾取某物”，但 E 实际先选渡口，扣木材/石头并修复。即使另有 H 修复说明，也不能消除这个矛盾。已修复出口和宝箱组合也要检查。

这是源码条件推导出的错误路径，未声称审核者已在 Unity 中复现。现有测试检查了 E 的距离优先结果，但没有证明 E 的可见提示使用同一个目标。

修复合同：
- 一个权威交互解析结果，同时供提示与执行消费。至少包含目标稳定 ID、动作类型、动作名称、实际键位、是否可执行、不可执行原因和费用。
- E 保持原有最近合法掉落/事件/出口语义；H 仍专用于出口，不擅自改绑定或变成远程回营。
- E 和 H 指向同一动作时合并显示；指向不同动作时在同一提示组件中呈现主/次动作，并分别写清动作、键位、目标和费用。
- 执行前重验目标存在、范围、状态与成本；目标过期时取消/刷新提示，不悄悄换到另一个付费目标。特别检查按键采样与最后可见提示不同步的边界。
- 不让不同 UI 控件各自 FindObjects/挑目标，再分别调用业务入口。

### 1.3 截图已证明的 UI 问题

- 顶部中央常驻检查点、坐标、弹体/前摇恢复、测试模式等开发信息。
- 左侧长期显示完整文字路线，地点距离还有溢出面板的情况。
- 底部渡口卡、通知条、拾取提示、翻滚状态与技能栏独立定位，出现遮挡和重复。
- `AdventureFlow.UI` 的渡口面板固定 115 高，即使只有一行“已修复”仍保留大块底色。
- `PlayerInventory.OnGUI` 的通知条与该面板占用区域交叠；仅调 GUI.depth 只会决定谁盖住谁。
- `CombatHud` 常驻完整键位、攻击/防御、击杀计数；探索模式全场击杀分母容易暗示需要清场。
- `CombatUI.Begin` 使用缩放坐标，部分世界/路线 OnGUI 使用屏幕像素。混用坐标与各自定位，不能保证分辨率改变后不互挡。

这次要解决信息架构、布局和交互一致性，而不只是换图标或降低字体大小。

## 3. 信息三层与布局

### 3.1 常驻：只保留影响当下决策的内容

| 区域 | 默认显示 | 移走的内容 |
| --- | --- | --- |
| 左上状态组 | 生命条及当前/最大值、小型等级标记、细经验进度 | 职业长标题、每帧攻击防御说明；详情进角色页 |
| 下方动作组 | 主/副武器图标、切换键、武器技能图标、翻滚、药水数量与实际冷却 | 手持/备用完整句、翻滚“就绪”常驻文字、重复快捷键段落 |
| 角落轻量信息 | 补给槽图标及已用/上限、区域短名、路线/帮助入口 | 整块测试说明、来源账、检查点坐标与版本 |
| 保存状态 | 正在保存时的小图标；成功后短暂反馈；失败时可读且持续提示 | 持续刷出的“检查点#”“退出续此点”说明 |

不凭空增加法力、耐力、任务进度或其他未实现的数据。探索模式不常驻全场击杀分母；原波次测试模式仍可显示它真实需要的波次/剩余敌人。

动作格建议的最小语义：图标中心 + 固定角落键帽 + 数量/冷却。就绪以正常亮度表达；冷却用遮罩/进度与必要秒数；不可用用灰态与明确原因，不只用颜色。

### 3.2 情境提示：只在有关时出现

交互区位于动作栏上方，与消息区和进度条有明确间距。无目标则整个收起，不保留空底板。

| 状态 | 建议显示（方括号是占位说明，不是实际 Emoji） |
| --- | --- |
| 可拾取木材 | `[E键帽] [木材图标] 木材 ×3` |
| 可开箱 | `[E键帽] [宝箱图标] 打开` |
| 未修且缺料 | `[修理图标] 渡口` + `[木图] 1/2  [石图] 1/1` + `缺木材1` |
| 材料足够且 E/H 均为修复 | `[E/H键帽] 修复渡口` + 材料持有/所需图标计数 |
| E 拾取、H 修复 | 主行明确 E 拾取；紧凑次行明确 H 修复及费用，不能混成同一句 |
| 已修复 | `[出口图标] [E/H实际键位] 撤离`；必要时短标签“已修复” |
| 引导中 | `[出口图标] 撤离中 3.2秒` + 进度条/环 + `[H]取消` |
| 引导中断 | 短暂显示 `受击中断` / `离开范围`，不重复滚出整段规则 |
| 保存未确认 | `保存中`或`等待核对`；禁止直接显示“已修复并保存” |
| 保存失败 | `保存失败，修复未生效`或`结果待核对，请重试`，必须依据领域结果区分，详情可展开 |

材料比例全项目统一为“持有/所需”，第一次使用及帮助中解释。图标计数不是只靠红绿区分；不足要有形状/短文字。

撤离计时必须读取实际 `ActiveRun.extractionRemaining`，不能在 UI 另起五秒计时器。暂停、受伤、取消、保存恢复后显示必须与原业务一致。

### 3.3 详情层：需要时可查看，不删除信息

- 路线全文改为可展开路线卡。可用已存在 POI/route 数据做只读节点图或结构化列表，不新增地图生成、迷雾和自动导航；当前已有的公开地点信息不被悄悄扩展为新情报。
- 收起时只显示区域名与路线入口；没有真实 B2 目标就不显示假“任务目标”。
- 操作说明放帮助，初次出现某项操作可短暂提示。不要常驻完整 WASD/Shift/E/H/F/V 段落。
- 属性、技能机制、装备来源与失败损失放角色/物品详情；高风险操作仍有短文字确认，不把“丢失战利品”“弃置不可恢复”变成无解释图标。
- 调试页保存 RunId、种子、版本、坐标、来源账、恢复约束。Editor/开发构建显式开启，默认关闭；正式构建不默认露出调试 HUD。日志和测试记录继续完整保存。
- 可以保留一个很小的“开发中”状态，不能隐藏未完成事实而冒充发布版。

## 4. 结算页的小范围调整

不重写结算状态机，只改变展示顺序与折叠方式：

1. 顶部短标题：成功撤离/冒险失败。
2. 首屏先显示本局新增收获与损失，装备/材料用图标、数量与短名。
3. 入场装备归还列表默认折叠为“入场装备已归还 · 8件”，可展开逐件核对。
4. 带入剩余、本局带回、制造后余额是不同指标，不能混算；来源详情可展开。
5. 内部 Pending/Committed 对应玩家文案“待确认”与“已保存”，准确读取实际状态。未提交不得显示到账成功。
6. 原“确认结算并保存”“返回营地”等动作和失败重试保留；没有用户授权不要合并成自动提交。
7. 满仓待领取、保存失败、主动放弃和不可逆丢弃继续清楚提示。

## 5. 工程实现约束

### 5.1 只迁玩家 HUD，不推倒现有系统

推荐使用工程已有 uGUI，新增一个统一的玩家 HUD Canvas/Prefab 与 Presenter。用 RectTransform 锚点、布局组件和 CanvasScaler 处理分辨率，不再叠加多组任意屏幕坐标。

保留当前包与版本，依赖清单以仓库实际为准，不新增收费插件、不升级引擎、不引入第二种新 UI 框架。完整背包/营地/工作台可继续沿用原展示；本轮只做上述 HUD 与少量结算展示，保留兼容桥。

新 HUD 启用后，明确关闭旧 `CombatHud.Draw`、`AdventureFlow.UI` 的运行期 HUD 分支、`PlayerInventory.OnGUI` 的运行期提示/通知分支及旧路线/出口标签分支。不能在旧 UI 上再盖一层。准备、放弃、结算、错误恢复等业务面板不能误删。

建议职责（名称可按工程惯例调整）：
- `InteractionResolver`：共享 E/H 候选、稳定 ID、动作、费用、原因；展示与执行同源。
- `PlayerHudPresenter`：从现有英雄/背包/冒险读状态，统一视图更新与显隐，不拥有第二份背包或结算。
- `ContextPromptView`：唯一交互卡与撤离进度。
- `HudNotificationQueue`：消息优先级与同类合并。
- `HudIconCatalog`：图标语义映射和缺失回退。
- `DeveloperHud`：仅开发诊断，不参与玩家提示和业务判定。

无需创建新通用框架、DI 容器、事件总线平台或复杂插件架构。只为当前需要建立足够小的接口。

### 5.2 输入与状态

- 不改现有 WASD、Shift、左键、F、V、空格、E、H、Q、Tab/B、C、R 的玩法语义；Esc 现有行为也不得悄悄变更。
- 新的帮助/路线面板入口先检查键位冲突；可使用未占用键和明确按钮，不能只靠鼠标悬浮才能了解必要操作。沿用现有鼠标解锁/面板状态管理。
- 图标按钮与快捷键都调用原领域入口，不重复执行；UI 焦点、点击、关闭帧和锁鼠状态有回归。
- 纯装饰层不拦截点击；背包、技能选择、结算、恢复阻断等面板出现时，按优先级隐藏无关 HUD 并避免输入穿透。
- 不因提示卡出现而暂停战斗或改变撤离取消规则。
- 图标冷却读取原技能/翻滚/药水数据，V 切武器后技能图标即时切换，但冷却不重置。

### 5.3 图标与可读性

优先复用 `AdventureItems.Texture`、已有物品/材料图标与合法素材，核对实际可读性后统一尺寸、描边、留白和底板。新补图标记录作者/来源/许可；自制的说明为自制。不用 Unicode Emoji 代替成套图标，不新增外部下载或购买前置。

建议覆盖：四武器、实际技能、翻滚、药水、装备背包、补给槽、路线、帮助、木材、石头、矿石、宝箱、修复、普通出口、渡口、保存、错误。

图标加载缺失时使用清晰短名回退，不能空白或显示缺字方块。图标不得成为必须猜测的谜语：首次说明、键盘可达详情和少量短文字保留。

普通提示/数字在最低支持分辨率实际可读；不要靠缩小到很小字号或滚动跑马灯达到“少文字”。小屏幕先收起低优先信息、换行/调整组布局，再考虑整体缩放。

### 5.4 通知与视觉层级

- 一次最多一条高优先错误提示与少量合并拾取反馈；相同材料短时间重复拾取可合并为总数。
- 保存失败/恢复受阻优先于普通拾取反馈，不能几秒自动消失而无恢复入口。
- 交互区、撤离进度、消息区和动作栏不重叠，不靠绘制顺序掩盖碰撞。
- 以轻量深色半透明底、清楚描边和有限强调色为建议方向，保持统一；不为了东方题材加满屏金边、纹样和常驻发光。
- 平时保持角色、准星和主要战斗视野清楚。避免上中下各占一块大面板。
- 世界图标只显示合适范围内的相关对象，超出屏幕正确处理。已有世界交互图标不能重复成两个标签。
- 同一数据不多处常驻；例如技能可用不同时在两块面板各写“就绪”。

### 5.5 性能与生命周期

已有代码含多处全场查询。本轮至少避免新 HUD 每个格子各自全场扫描：统一收集/缓存目标与引用，事件或状态变化时更新文字，连续进度只更新必要图形。

不要每帧创建纹理/材质/加载 Resources；可缓存纹理转 Sprite，并在正确生命周期释放。反复出征、死亡、恢复、回营后只能有一套 HUD、一套输入处理，不出现重复订阅或重复扣费。

不宣称已经优化了整体游戏性能；记录同场景 UI 开关/更新的实际指标，未测写 NOT_RUN，不以“使用 Canvas”直接推导更快。
